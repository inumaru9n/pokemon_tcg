# /batch-experiments — 大量アイデアの並列検証

引数（任意）: 検証するアイデア数、またはアイデアIDのリスト。

## 手順

1. **アイデア出しフェーズ（常に最初に行う）**: /ideate の手順（材料リスト含め原本は `.claude/skills/ideate/SKILL.md`）を実行してBACKLOGを拡充する。目標検証数に対して `proposed` が不足していれば必ず埋め、足りていても直近の実験結果を反映した新アイデアがないか一度は検討する
2. `knowledge/BACKLOG.md` から `proposed` のアイデアを優先度順に取り出す
3. **番号の事前割当**: 既存の `agents/` 最大番号+1から連番で、各アイデアにエージェント番号NNNを割り当てる（衝突防止のため親が一括採番）。対象アイデアのBACKLOG状態を `in-progress` にまとめて更新
4. **バッチ実行**: experiment-runner サブエージェントを **同時2〜3体まで** のバッチで起動（バックグラウンド実行）
   - プロンプトに必ず含める: アイデアIDと内容 / 割当番号NNN / 現行ベストのパス（experiment-runnerの「入力」定義と対応）
   - このマシンは4コアであり、対戦評価(-w 2)が並走するため同時起動数を増やしすぎない
5. **結果の取り込み**: 各サブエージェント完了ごとに親が行う（サブエージェントはBACKLOG/INSIGHTSを触らない）:
   - BACKLOG状態更新（validated / rejected / 保留 / 実装失敗）+ EXPリンク
   - INSIGHTS昇格候補の知見を検討して追記
   - validatedが出たら `uv run arena/league.py` で現行ベストを再判定し、INSIGHTS冒頭を更新
   - 次のアイデアがあれば新しいサブエージェントを投入（常時2〜3体を維持）
6. **最終報告**: 全体サマリ（検証数、validated/rejected内訳、新ベスト、得られた主要知見、有望な派生アイデア）

## 注意

- 長時間になる場合も途中経過をユーザに報告しながら続行する
- 同一アイデアの再検証を避けるため、起動前にBACKLOGの状態確認を必ず行う
