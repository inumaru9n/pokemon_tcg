## 0. 現行アーキ（058/075/059）の解剖 — どこがルールでどこがモデルか

```
観測 → [B2 ルール: 126次元ゾーン特徴の計算（資源勘定・1-ply述語・結合述語）]
     → [B4 ルール+探索: lethal確実性オーバーライド（全決定化サンプル勝利時のみ）]
     → [A1 モデル: MAIN行動クラス予測 GBT（31-37クラス）]     ← 059は [A2 モデル: DISCARD二値GBT] も
     → [B3 ルール: クラス→具体optionの具体化（052サブ選択資産）]
     → [B5 ルール: 非管轄ctx・モデル不発時のフォールバック（052条件文policy）]
     → [B8 ルール: ターン内実行順序（RULE_E較正順序）]
```
- 見落とされがちな分担: **ラベル空間（31クラスの切り方）・特徴量・管轄の選定・教師の選別も
  すべてルール（ドメイン知識）の仕事**。モデルは「観測可能なターゲットの予測」だけをしている。
- 075 = 058 + turn1拡張（モデル管轄をturn1へ。vs058中立、EXP-072/075）。
  076 = confgate（モデル信頼度ゲート、null）。

## 3. 設計原則（カタログから読める法則）

1. **モデルに任せて成功したのは「観測可能なターゲットの予測」だけ**（本人の行動クラス・対象、
   将来は相手の実行動）。「評価」（価値・優劣・信頼度）を任せた試みは全滅（P6/P7/P9）。
2. **ルールの本業は問題の定義**: ラベル空間(B1)・特徴量(B2)・管轄(B6)・教師選別(B9)・目的関数(B10)。
   実行時にモデルと張り合う仕事（veto/抑制/骨格置換）は全滅（P13/EXP-061/065）。
3. **ルールの実行時の生き残りは3つだけ**: 証明できる時のオーバーライド(B4)、クラス内の具体化(B3)、
   管轄外のフォールバック=背骨(B5)。
4. 新パターンを考えるときのチェックリスト:
   - モデルの予測ターゲットは観測可能か（実現しなかった選択肢にラベルが要らないか）→ Noなら交絡（P6）
   - ルールの関与は「定義側」か「実行時の抑制側」か → 抑制側なら7連敗の同型（P13）
   - その管轄のleverageは高いか（頻度×資源計算の重さ）→ 一致率の伸びで判断しない（EXP-060）
   - オフライン指標で較正するなら過学習前提でホールドアウト+fire診断（P14/EXP-054）

## 4. 結論

設計空間 A×B×C を洗った結果、**未検証で生きているセルはほぼ既にBACKLOGに登録済み**
（I-118/I-125/I-122/I-114/I-115/I-068/I-109）であることを確認。純粋な新規は
P17（量予測ヘッドの一般化→I-125に統合）と P20（逆蒸留=Strategyレポート素材）のみ。
残る最大の空白は軸として「実行時の分担」でなく**「学習時の目的関数の分担」（B10/A8オンライン）**
であり、これがI-122/I-123路線の位置づけを裏側から支持する。
