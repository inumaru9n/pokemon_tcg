## 機序

`opp_left_{cid}` / `opp_phand_{cid}`（20枚）は「相手のアーキタイプが分かれば60枚は既知」
という前提で残枚数と手札確率を計算する。**ミラー戦では相手の構成が自分と同一なので推定が最も正確**
になり、異種デッキでは粗くなる。

さらに**訓練データ（Yushin 07-17〜29）に Ogerpon も Lopunny も存在しない**ので、
それらの相手に対する「隠れ情報の使い方」は一度も学習されていない。

## 判断: **117を置き換えない**

本番メタで Alakazam は 6.3%。重み9.7%の Lopunny で −3.2pt 落とすのは割に合わない。

## ★ 副産物: 「直接対戦は非推移」の明確な実例

CLAUDE.md の「直接対戦は非推移で本番性能を予測しない」を、**両方を2回ずつ再現する形で確認**した。

```
直接対戦（ミラー）  53.0% 有意に強い      ← 2シードで再現
プール加重          −0.12 / −0.23pt      ← 2シードで再現
```

単発の測定ではなく、**どちらも安定した事実として両立する**。
候補の採否は必ずプール（=本番の分布モデル）で判定すること。

## ★ 重大な事故: 派生エージェント作成でカードIDが壊れた

`open(p).read().replace("117", num)` という素朴な置換で、**カードID 117 が エージェント番号に化けた**。

```
feat_137.py:  (117, 'Claw Slash')  → (137, 'Claw Slash')
feat_134.py:  (132, 'Will-O-Wisp') → (134, 'Will-O-Wisp')
```

症状は「feat_keysの並びがモデルと不一致 → NN無効化」で、**errors=0 のまま対戦が進む**。
136/137 では113件のNN無効化が出て、対Garchomp 15.2% という異常値で初めて気づいた。

**被害範囲**: 133/134/135/136/137（ローカル評価用）のみ。
**提出物（104/117）とKaggle学習データ・重みには影響なし**（生成ツールが直接作った原本）。

**対策**: `tools/make_variant.py` を新設。
- 置換は**モジュール名として現れる箇所だけ**（正規表現 `\bfeat_117\b` 等）
- 作成時に **ATK_COST / ATTACKS_056 / DECK_COUNTS / CLASSES が元と一致するか assert**
- `nn_*.py` は必ず `tools/featgen_nn.py`（唯一の定義元）から配る

作り直して再測定した結果、軸Bの結論（効果なし）は変わらなかった
（壊れたカードID 132/133=Gengar は我々のデッキにもプールにも入っていないため）。
