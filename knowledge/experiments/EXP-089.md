## 仮説

メタ最大シェア38.4%のMarnie's Grimmsnarl（sig 1ec0f47981、07-22覇権個体）に水平展開すれば、

**MLはMAINのみ・082ルールを背骨として維持**する。

## 方法

- **教師の選定**: sig 1ec0f47981は複数チーム使用だが、頻度・日付・勝率から**本家はLuca**と特定
  （07-16に単独出現107戦65.4%→07-17 903戦61.8%。他チームは07-18以降のコピー勢で勝率が一段低い:
  07-22はLuca 57.1% vs コピー勢中央値~47%）。**教師はLucaに限定**（公開レシピの混合方策問題を回避）。
  dev=07-16〜18（1,976エピソード、78,950 MAIN決定）、val=07-22（368エピソード、15,247決定）の日付分割
- **クラス体系**（feat_089.py）: 教師のctx0選択を頻度集計してから設計（07-16、4,359決定）。
  34クラス=攻撃3種別（bullet/cork/filch）+ ability 3種（**ab_munki=Adrena 12.7% / ab_gym=
  Spikemuth Gym効果 9.9%** / ab_grim）+ attach貼り先5バケット + サポート/グッズ12種 +
  put3種 + evo3種 + retreat/end/other。**発見: ABILITY optionのarea=7はSTADIUM**
  （Spikemuth Gym効果使用。bench誤解決だと5%超がab_otherに化ける。要stadium[index]解決）
- **特徴量**: feat_058の構成法を1ec0の60枚に再設計、127次元（手札/トラッシュ/山∪サイドプールの
  ID別19種×3 + 自field結合述語 ready_grim/charged_pre/munki_online/field_dmg_me(Adrena弾) +
  相手属性 + Marnie対面述語 opp_wall_active/opp_megakang_bench/opp_n_ability + 資源勘定 + フラグ）
- **学習**: LightGBM multiclass（train_058パラメタ踏襲）、評価は実運用と同じマスク付きargmax
- **統合**: main.py=082のコピー（policy_scores/policyに分離しただけの逐語コピー）+ _ml_layer
  （MAIN・turn≥2・min=max=1のみ: クラスargmax→クラス内は082policyスコアで具体option化）。
  モデル無し/F089_ML=offで082と同一挙動。npz純Python推論への移植=argmax一致3000/3000=100%
- 対戦条件: スモーク20戦 → vs082直接400×2（--engine-seed 1140001 / 2250001+--seed 7）→
  プールv4 n=200（seed 42）→ vs075直接400（--engine-seed 3360001）

## 結論

**validated。057定式化の水平展開2例目が成立し、「クラス直接学習はアーキタイプ非依存に
ルール背骨を上回る」ことを実証。089は075（現行運用ベスト）に直接57.1%で勝ち、
075の2大不利対面（Marnieミラー・Spidops 30%）を53%/69%に反転する異アーキヘッジ**。

1. **成功の再現性**: 一致率0.565→0.725（+16.0pt）、fire純増+2,432、アリーナ+6.1pt（vs背骨直接）。
   057（0.55→0.77、vs052 66.6%）より利得は小さいが同じ形。差の解釈: (a)082背骨は軽量逆設計製で
   052（フル精読+磨き込み6世代）より粗く、クラス内の具体option化資産が弱い
   (b)教師データが4日分（057は2日分だが決定数は倍）(c)Marnieの決定はAdrena/Punk Upの
   ダメカン算術に依存し、クラス選択だけでは写らない部分が残る
2. **ML層の利得はほぼ「対教師系統（ミラー）」に集中**: 非ミラー対面は中立（±ノイズ）。
   模倣学習の改善は「教師の分布内の局面」で最大化され、異アーキ対面の質は背骨の対面知識で
   決まる、という描像と整合的（EXP-088のML層汎化実証とは相補的: あちらは層の除去で-17pt、
   こちらは層の追加でミラー+6pt/非ミラー±0）
3. **手法知見（水平展開の再利用手順）**: ①教師sigはチーム別に頻度×勝率×初出日で本家を特定して
   限定する ②クラス設計の前に必ずctx0頻度集計（ABILITY area=STADIUMの罠はこれで発見）
   ③082系のようなplanグローバルを持つ背骨は policy_scores() に副作用ごと分離すれば
   _ml_layerのクラス内tie-breakと非MAIN層が既存挙動を保つ
4. 残課題: (a)テールスポットチェック未実施（Froslass 1.3%/Thwackey 1.2%等。主力確定前に必要）
   (b)非MAIN管轄（DISCARD等=059方式）のMarnie版は未着手 (c)Boss吊り先・Adrena配分など
   ダメカン算術系サブ選択は082ルールのまま（一致率天井の候補）(d)日次再学習の運用
   （dev+val合流再学習で最終提出前に更新可能）
