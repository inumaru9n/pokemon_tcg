# EXP-080: TO_HAND（サーチ先）二値ランカーの管轄化

- 日付: 2026-07-23
- BACKLOG: I-118
- エージェント: `agents/080_search_ranker/`（ベース=075_058_turn1、ユーザ指定）
- 状態: **rejected（中立。一致率⊥アリーナ寄与の4例目）**

## 仮説

弱点マップで最大級の未管轄ctx=TO_HAND（サーチ先選択）は、DISCARD（EXP-059、+4.1pt）と同じ
「山資源の取捨選択=高leverage」型。059の二値ランカー形式（カードID one-hotで対象そのものを
特徴化）を適用すれば、RULE_Cの固定スコア表を超えて転移するはず。

## 方法

### 管轄設計（実装調査で判明した事実に基づき当初案から修正）

- **リプレイの`select.deck`は263/640決定で空**、また「TO_HANDの大きな塊」の正体は
  **サイド取り（PRIZE area、裏向き=情報ゼロで学習不能）**だった。管轄は
  「全候補がカードIDに解決できる決定」（山開示サーチ[area=DECK]+トラッシュ回収[DISCARD]+
  LOOKING）に限定。PRIZE取り・解決不能はルール続投
- **実サーチの主流はmin0/max1「1枚まで」型**（教師は228/228で必ず1枚取る）。k固定
  (min==max≥1)に加えこの型をk=1として管轄化。可変枚数(min1/max3等、4%)はルール続投
- 層の位置: lethal → MAIN ML → （TO_HANDのみ）ランカー → 052ルール。
  model_tohand_080無し/F080_TOHAND=offで075と完全同一（CRN 20戦全レコード一致で検証）

### 学習

- 教師: Yushin 81f1のTO_HAND決定。dev=07-09〜15（20,149決定/103,954行）、
  val=07-16〜18（4,542決定）。take-rate 0.194
- 特徴: feat_080.to_hand_feat_vector = 058ゾーン特徴 + カード属性（ID one-hot・手札内枚数・
  プール残・進化ライン需要）+ サーチ文脈（from_discard・即効性c_usable_now）
- ベースライン: **同一管轄・同一決定上でのRULE_C実選択**（収集時に記録。弱点マップの0.840は
  PRIZE取り等を含み比較として不正確）
- LightGBM二値1000木 → npz純Python移植（選択一致4542/4542=100%、0.49MB、6.15ms/候補）

## 結論

**rejected（中立）。オフライン一致率+5.7ptがアリーナに転移せず（+0.5pt±3.4）。
一致率⊥アリーナ寄与の4例目（EXP-052-E順序/060/070に続く）。075は変更せず現状維持。**

1. 劣化なしは全評価軸で確認（直接50.5%、プール77.5%≥75.3%、全対面ペア差分がCI内）。
   ただし採用には利得の証拠が必要（EXP-070の教訓: 証拠なき「無害な改善」の採用が本番-80pt
   を招いた）で、中立の変更を積むことはしない
2. **「サーチ先=資源選択=高leverage」の事前予測は外れた**。DISCARD(EXP-059)が効いたのは
   Xerosic被弾時の手札取捨=不可逆で大きい資源スイングだったから。サーチ先は「どれを取っても
   数ターン内に他のアウトで到達できる」冗長性が高く、僅差の判断が勝敗を動かさない
3. 管轄拡大ファミリーはDISCARD以降、SWITCH/TO_ACTIVE(060)→turn1(072/075)→TO_HAND(080)と
   3連続で「オフライン改善・アリーナ中立」。**残りマス（evolve細分化・boss吊り先ランカー等）の
   期待値も下方修正すべき**
4. 副産物: (a)リプレイのselect.deckは4割空でPRIZE取りは学習不能=TO_HAND系の管轄設計知見
   (b)CRNペア測定が単発プールの偽陽性(+9pt)を1時間で棄却=改良系判定の標準手順として有効
