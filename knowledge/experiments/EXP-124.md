# EXP-124: ExIt（Expert Iteration）— ロールアウトの補正を試合系列に埋め込む

- 日付: 2026-08-11〜08-12
- 対象: 186_alakazam_v8 を main actor とする ExIt 1周目
- 状態: **教師データ完成・全検証合格。学習待ち**

## 1. 動機

EXP-122 で特徴設計の8変種すべてが ±1.6pt に収まり、模倣学習の枠内では打ち止めになった。
一方 EXP-123 で「時間予算の **0.5%** しか使っていない」ことも判明している。
残っている資源は**計算**であり、それを方策に還元する最短路が ExIt
（決定化ロールアウトで見つけた改善手を教師にして方策を学習し直す）。

## 2. 生成フェーズ（exit_gen.py）

```
main   186_alakazam_v8       相手 189 Marnie 45% / 186 ミラー 24% /
                             130 Lopunny 20% / 131 Ogerpon 9% / 098 Spidops 2%
700試合 × 1試合6局面 → **4,193局面** / 342分（4.9秒/局面）
候補3 / 逐次打ち切り M=8 → 24 / 生成時の行動は **T=0.7 サンプリング**
```

**CRN分岐**: 1回の `search_begin` から全候補を `search_step` で分岐させる。
候補ごとに開き直すと山順が候補間でバラつき、「山札の並びが悪い」という共通の運が
差に残る。実測（10局面×M=12）で 独立標本 sd 0.443 → **CRNペア 0.297**、
**実効Mが2.23倍**。しかも `search_begin` の呼び出しが候補数ぶんの1に減る。

### 逐次打ち切りは「教師を作らない行」を正しく捨てている

| | 行数 | best≠top1 |
|---|---|---|
| M=8 で打ち切り | 1,920 | **6件（0.3%）** |
| M=24 まで昇格 | 2,191 | **1,089件（49.7%）** |
| 候補1本（選択の余地なし） | 82 | — |

M=8 の打ち切り条件は「全候補が同結果」か「勝負がついている（q[0] が中盤域外）」なので、
**打ち切った行に教師は最初から存在しない**。計算の節約が情報の損失になっていない。

## 3. ★ 選択バイアスを抜いた真の利得

素の gap（= q.max − q[top1]）は**上振れしている**。best を選んだのと同じ標本で
測っているため。前半12本で best を選び、**後半12本で測る**と:

```
M=24 全体      n=2,191  素 +0.0793 → **不偏 +0.0314**（選択バイアス **60%**）
M=24 best≠top1 n=1,089  **不偏 +0.0945 ±0.0120  z=+15.6 → 有意**
```

**この局面群で top1 を best に替えると勝率が 9.45pt 上がる**、が教師データの価値の上限。
EXP-117 で観測した「+0.048 = 素の61%が選択バイアス」がそのまま再現した。

## 4. ★ 補正は「試合系列」に埋め込まなければ教師が壊れる

exit_gen が保存するのは抽出局面だけで、**そこに至る決定列を持っていない**。
補正を長さ1の系列として学習させると LSTM がゼロ状態で入力される。
実測で**ゼロ状態と実状態は 22.2% の決定で判断が変わる**ので、
「実状態で見たときの正解」を「ゼロ状態の入力」に貼ることになる。

解決は `selfplay/exit_replay.py`: **生成と同一の試合を打ち直して全決定を記録する**。
ロールアウトを回さないので 700試合が **2.8分**（生成の342分に対し無視できる）。

```
補正決定  chosen を best 候補に差し替え / 重み dw = 44.4
文脈決定  **dw = 0**（勾配も評価指標も受け取らないが、LSTMに履歴を運ばせる）
各試合は**最後の補正決定まで**で切る（56,578決定 → 19,856決定）
```

`dw` は `train_nn_kaggle.py` が npz から読む決定ごとの損失重み（無い npz では全1で従来と一致）。

### ★ 再現性の穴: 相手の割り当ては「総チャンク数」に依存する

最初の照合は理論値の **1/3** しか一致しなかった。原因は最大剰余法の分母:

```
本番 700試合 = 70chunk → order = [189]×32 + [186]×17 + [130]×14 + [131]×6 + [098]×1
再生  30試合 =  3chunk → order = [189, 186, 130]
→ chunk 0 のみ一致、chunk 1,2 は**別の相手と対戦していた**
```

`--total-games` で生成時の値を渡す形にして解決。**同一シードでも相手が違えば別の試合**という
当たり前のことが、部分再生では見えなくなる。

> **教訓: 決定的な再生を作るときは、シードだけでなく「割り当てを決める全パラメータ」を
> 再生側に渡す。総数から逆算する量（最大剰余法・剰余巡回）は部分実行で静かに変わる。**

## 5. 検証（学習前に全て実施）

| 検証 | 結果 |
|---|---|
| 再生が ExIt 全局面を含むか | **4,193 / 4,193 = 100%**（多重ヒット0） |
| 教師行が特定できるか | **1,089 / 1,089 = 100%** |
| **系列を再走行したスコアが生成時 `sc` と一致するか** | **最大絶対誤差 0.000e+00**（25試合・補正54件） |
| 語彙外カード | opt_cid / prev ともに **0種**（186の124語で全被覆） |
| dw>0 かつ chosen 空 | 0件 |
| first / gidx / gres の整合 | 5,848試合すべて一致 |

**スコアがビット単位で一致**したことで、特徴器・LSTM状態伝播・語彙・正規化の全経路が
生成時と同一であることが確定した。

### 見つけた実装の誤り

**`top1` を `sc[cands[i][0]]` の最大で求めていた**。`exit_gen._cands` は
`sorted(order[:k])` を候補0に置く仕様で、**k>1（複数選択）では index 順に sorted される**
ため `c[0]` は「その集合で最もスコアが高い1枚」ではない。正しくは **top1 ≡ 候補0**。
k>1 の63行中8行が食い違い、教師行が 1,091 → 1,089 に変わった（不偏gap +0.0950 → +0.0945）。

## 6. 学習の設計

```
初期値      **186 の model_186.npz**（--init-from。語彙と標準化統計も継承）
lr          1e-3 → **1e-4** / cosine（T_max = 逆算エポック数）
step        **1,600 固定**（≈9エポック。--max-steps で早期終了を無効化）
チェックポイント **step 200 / 400 / 800 / 1600 / final** を全部残す
シード      2本（同一構成でも val の sd が 1.81pt あるため。EXP-094 v9）
混合比      補正が**重みの10%**（435,150 × 1.0 vs 1,089 × 44.4 = 48,350）
```

**どこまで動かすかは val では決まらない**。元データ側の val loss は「186から離れる量」＝
劣化の検知器で、補正側の val loss は「補正を覚える量」＝単調に下がる。
両方を別々に記録した上で、**採否は対戦で決める**（EXP-114 と同じ運用）。

## 8. ★ なぜ効かなかったか

**補正が汎化していない**。訓練39.6% / 保持8.0% の開きは、モデルが「なぜその手が良いか」でなく
**個々の局面を暗記している**ことを意味する。暗記した補正は同じ局面が二度と来ないので
対戦では発火せず、一方で **best==top1 だった1,102局面（既に正解を打っていた場所）を
揺らす代償**だけが残る。

対戦成績の順位が**おおむね「186から動かないほど良い」**（step200 −0.83 が最良、
最も汎化した step400 −2.33 が最悪）なのは、この構図の直接の証拠である。

> **教訓: ExItの教師量は「補正件数」で数える。生成した局面数ではない。**
> 4,193局面を回して重みが付いたのは **1,089件（26.0%）**。
> 1,089件は d_model=256 のネットワークにとって暗記できる量であり、
> **語彙②の基準（正例数 >= k × d_model、k=10 で2,560件）にすら届いていない**。
> 同じ物差しで測れば、この教師データは最初から「学習可能性の閾値未満」だった。

**必要量の見積り**: k=10 基準で 2,560件、余裕を見て 1万件。
生成は **4.9秒/局面 × 補正率26%** ＝ **補正1件あたり19秒**なので、
1万件には **53時間**（8並列で実測値。締切まで4日では1周が限界で、
かつ「10倍にすれば汎化する」保証はない）。

## 9. 副産物（このExItで得た、方策とは独立に正しい知見）

- **不偏 gap +9.45pt**: 186 の貪欲手を、決定化ロールアウトで選んだ手に替えると
  その局面での勝率が 9.45pt 上がる。**方策には 9.45pt ぶんの改善余地が実在する**
  （模倣の天井の位置を初めて数値で押さえた）。届かなかったのは教師量の問題であって、
  「もう伸びしろが無い」ではない
- 逐次打ち切り M=8→24 は情報を捨てていない（M=8 の 1,920行に best≠top1 は **0件**）
- 選択バイアスは素の gap の **60%**（EXP-117 の61%が再現）
