# EXP-142: two-tower を cross-encoder にする — 一番醜い部分が一番効いていた

- 日付: 2026-08-17
- 対象: L1（222の構成要素）の採点部を、内積+cls_head から **joint MLP** に置換
- 状態: **棄却**。val **−0.54pt**（t=−7.8）/ MAIN **−1.02pt**。
  ただし **「two-tower の制約が効いている場所」を非MAINに特定できた**

## 1. 動機は性能でなく構造の負債

現行は two-tower（`score = dot(q(h), e(o)) + cls_head(h)[cls]`）で、そのために生じた負債:

| # | 負債 | 実測 |
|---|---|---|
| 1 | `ctx_bias` が死んでいる | 全選択肢に同じ定数。softmax も argmax もシフト不変＝**出力に一切影響しない** |
| 2 | `ctx_scale` のゲージ自由度 | 49×64 だが `proj` に対する自由度は 48×64 |
| 3 | 65クラスが**デッキ固有** | `CLS_PLAY`/`CLS_EVO`/`CLS_AB`/`CLS_ATK`/`ATTACH_BUCKET` を deck.csv から生成 |
| 4 | `ATTACH_BUCKET` が粗い | Abra(741) と Kadabra(742) が同一クラス `abra_p` |
| 5 | 採点式が2種類 | `cls_head` は MAIN のみ（`opt_cls>=0`）。非MAINは内積だけ |
| 6 | カテゴリを生の序数で渡す | `opt.type`=7/9、`opt.area`=2 を実数として MLP へ |

表現力の面でも、**内積は双線形＝相互作用が d_opt=64 本の軸に制限される**。
検索分野の bi-encoder / cross-encoder と同じ対立だが、**two-tower を選ぶ本来の動機
（アイテムを事前計算してインデックス化）を我々は一切享受していない**
（選択肢は5〜30個で毎回の盤面から作られ、再利用が効かない）。

## 2. 設計

```
score_i = j_out( ReLU( **j_h(h)** + **j_o(o_i)** ) )
o_i = [ card_emb(32), **type_emb(16)**, **area_emb(8)**, target_card_emb(32), 数値(28) ]
```

- **第1層を因数分解**して `(B,T,O,371)` を実体化しない（h側は1回、o側はO回）
- **容量は据え置き**（788,995 → **792,786**、+0.48%）。EXP-140 で容量が効くと
  分かっているので動かさない
- **joint では proj / ctx_scale / ctx_bias / opt_enc / cls_head を確保しない**
  （死重に weight decay が掛かるのを防ぐ。保存される重みは j_* と type/area_emb のみ）

3水準を**同一runで交互順**に3シードずつ（9本）:

| 構成 | パラメータ | 内容 |
|---|---|---|
| base | 788,995 | 現行 L1（=222の構成要素） |
| jcls | 809,491 | joint + cls_head 併存 |
| joint | 792,786 | cross-encoder のみ |

## 3. ★ 結果

| | val | MAIN | 同点決定 | ctx3 | ctx7 | **ctx8** | ctx9 | **ctx15** | **ctx30** | ctx43 |
|---|---|---|---|---|---|---|---|---|---|---|
| **base** | **0.8736** | **0.8380** | **0.8105** | 0.8664 | 0.9211 | 0.2856 | 0.8424 | 0.5641 | 0.4489 | 0.9769 |
| jcls | 0.8718 | 0.8361 | 0.8089 | 0.8641 | 0.9202 | 0.2856 | 0.7862 | 0.5641 | **0.5600** | 0.9777 |
| **joint** | 0.8682 | 0.8277 | 0.7973 | 0.8600 | **0.9242** | **0.3292** | 0.7942 | **0.6923** | **0.5600** | 0.9773 |

```
**joint − base**  val **−0.54pt**（3シードとも同符号、sd 0.12、**t = −7.8**）/ MAIN **−1.02pt**
**jcls  − base**  val −0.18pt（t = −1.9、**有意でない**）/ MAIN −0.19pt
```

事前登録した3つの読み方のうち **「joint_cls だけ base 並み → 枚挙は必要」** に該当。

## 4. ★ 機序: 損得が cls_head の管轄で分かれる

```
**MAIN（cls_head が効く）**          **−1.02pt**   ← 損失は全部ここ
**同点決定（内積が単独で決める）**     **−1.32pt**

**非MAIN（内積しか無かった場所）**
   ctx 15 DAMAGE           **+12.8pt**
   ctx 30 DISCARD_ENERGY   **+11.1pt**
   ctx  8 DISCARD           **+4.4pt**
   ctx  7 TO_HAND           +0.3pt
   ctx  9 TO_DECK           −4.8pt
```

**① 65クラスの枚挙は「醜いが load-bearing」だった。**
`cls_head` は意思決定分散の9割を担い（実測 A sd 7.49 vs B sd 0.78）、
**MAIN決定内のクラスの77.3%は選択肢1個**＝クラスが決まれば答えが決まる。
joint はそれを `(card_emb, type_emb)` から学び直す必要があり、
435,150決定では届かなかった（`jcls` が base 並みなのがその証拠: cls_head を戻せば回復する）。

**② 予想外: 同点決定でも joint が負けた（−1.32pt）。**
同点は「cls_head が割れず内積が決める」場所なので cross が勝つと予想していたが逆だった。
説明: **同点の57.8%は「手札スロット違いの同一カード」で、教師は99.5%で最小indexを選ぶ**。
内積は `index` という1次元の単調な手掛かりを素直に拾えるが、
joint MLP はそれを他の全特徴と一緒くたに学ぶことになる。
**単純な規則は、単純な形（双線形）の方が学びやすい。**

**③ two-tower の制約は実在し、効いている場所は非MAINだった。**
内積しか無かった ctx で cross が明確に勝つ（DAMAGE +12.8 / DISCARD_ENERGY +11.1）。
`jcls` でも **ctx30 だけは +11.1pt** 出ており、cls_head を残しても joint 項が効く。
ただし ctx 8+15+30 は val 決定の **1.2%** しかなく、全体では埋もれる。

## 5. 教訓

> **「醜い」と「不要」は別。負債の中に load-bearing なものが混ざっている。**
> 65クラスのデッキ固有表は設計上の最大の負債だが、**消すと −1.02pt（MAIN）落ちる**。

> **表現力を上げると、単純な規則が学びにくくなることがある。**
> 同点決定（最小indexを選ぶだけ）で、双線形の内積が MLP に勝った。

「美しくする」と「222 と同等以上を保つ」を**同時に満たす構成は、この設計空間には無かった**:

```
joint   美しい（負債6個が消える）が **−0.54pt / MAIN −1.02pt**
jcls    ほぼ同等（n.s.）だが **負債の返済はゼロ**、しかもパラメータ最多（809,491）
```

## 7. 実装上の記録

- **zsh は引用符なしの変数を単語分割しない**。`H="--head joint"` を `$H` で渡すと
  1引数になり argparse が usage を吐く。9本すべてが黙って失敗した
  （このセッションで2度目。**複数語の引数はリテラルで書く**）
- `head` で**構造そのものを分岐**させ、使わない部品は `None` にして確保しない。
  死重は weight decay を受け、npz にも載って提出物が太る
- プール評価は**未実施**。joint の numpy 推論（`nn_*.py`）が未実装で1.5〜2時間かかる一方、
  MAIN（決定の58%・誤差の74%）で −1.02pt 落としているため回さずに閉じた
