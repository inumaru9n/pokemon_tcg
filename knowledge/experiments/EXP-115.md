## 動機

本日までに失敗した全ての手法が、**同じ壁**で死んでいる。

| 手法 | ラベル | 結果 |
|---|---|---|
| 軸A/B/C（特徴・構造・損失） | 教師の手 | すべて判別不能 |

## ★ 前提検証（すべて実測で確認）

| 検証 | 結果 |
|---|---|
| search_begin でクローンした盤面が実戦と一致するか | **turn/自手札/山残/サイド すべて 8/8 完全一致** |
| 隠れ情報を推測せずに済むか | ✅ `GetHiddenData` で**真の値**を渡せる（criticのために実装済み） |
| 1回の search_begin から複数候補に分岐できるか | ✅ **可能**（全候補が同じ山順を共有＝CRN） |
| search_begin を呼び直すと山順が変わるか | ✅ 変わる（実測: 山残 11/12/9）→ **Mサンプリング可** |
| ロールアウト中に両プレイヤーを操作できるか | ✅ 可能（相手側の決定20回を我々が供給）→ **実プールの方策で相手を動かせる** |
| 推定 Q と実戦の結果 R の整合 | **相関 r=0.894**（n=8。要再確認） |

### EXP-053（探索5連敗）の死因は2つとも解消済み

```
死因1「決定化した相手が受動的」
   正体: 相手の山・手札を**全て同じカードで埋めていた** → 勝率1.000に振り切れる（実測）
   対処: **ARCH_DECK（各系統の実60枚、本日 tools/gen_meta_cards.py で作成）**で埋める
         → 勝率 0.950/0.833 と現実的に
   さらに: オフライン生成では **GetHiddenData で真の値**が使える＝推測すら不要

死因2「N=8では±2-5%の差が解像度外」
   対処: M を適応的に増やす（M=213 で±5pt を検出可能と実測）
         + **同一rootからの分岐でCRNペア**にして分散削減
```

### search_begin と前方リプレイの関係

| | 隠れ情報 | サンプル数 | 1局面(候補3) | ラベルの質 |
|---|---|---|---|---|
| 前方リプレイ | 不要 | 1（決定的） | **1.2秒** | 雑（0/1の1サンプル） |
| **search_begin × M** | **必要**（真の値を渡す） | M | 45秒（M=64） | **正確（勝率）** |

前方リプレイは search_begin の M=1 特殊ケースに相当。検証Bの相関0.894は両者の整合を示す。
**「勝率で比較する」という目的には search_begin 方式を採用**。

**注意**: seed が同じでも、分岐で乱数の消費量が変わると**その後の山順はずれる**（実測: 分岐直後から不一致）。
「山順が凍結された同一世界」ではなく「同じ乱数列を共有するCRN」である。

## 手順

### Step 1. データ生成
```
Actor  104（自分 T=0.7）/ 相手 argmax
相手   自己(104) / 101 Marnie(w48.3) / 131 Ogerpon(7.2) / 098 Spidops(2.7)
       ※ 忠実度ゲート合格枠のみ。084/085/041/021 は本番より20〜39pt弱いので除外
       　（偽の局面分布になる。EXP-095 の設計判断と同じ）
記録   observation / legal action / policy / 隠れ情報 / エンジンシード
```

### Step 2. 局面選別
主軸は **top1 − top2 が近い**（方策が迷っている局面）。
実測で**85%の局面はどの手を打っても結果が変わらない**ので、ここの足切りがコストの8割を決める。

### Step 3-5. 候補評価
```
for m in 1..M:
    root = search_begin(s, 真の隠れ情報)      # 山の中身は本物、順序を再抽選
    for a in [top1, top2, top3]:
        ch = search_step(root.searchId, [a])  # 同一rootから分岐＝CRN
        終局まで: 自分=feat_104/model_104 argmax / **相手=相手の feat/model** argmax
Q(a) = M本の平均勝率。M=32 で差が明確なら打ち切り、僅差なら213まで
```

### Step 6. 教師データ化 — **方式B（結果が割れた局面すべて）**
```
全候補が同じ結果 → 捨てる（情報なし）
結果が割れた     → **勝率最良の候補を教師にする（それが top1 でも採用）**
```

**「別候補が勝った局面だけ」を拾うと偏る**: 真に差が無い局面で
「Aだけ勝つ」を捨て「Bだけ勝つ」だけ拾うと、**必ず現行と違う手が教師になる**。
M本の推定＋有意差の閾値を入れれば偏りは 25%→2.5% に縮むが、
**「現行が勝った」を拾うコストはゼロ**（Q は全候補について既に計算済み）なので両方拾う。
AlphaZero系のExItも全局面にラベルを付けるのが標準。

### Step 7. 再学習
```
元expert + ExIt教師（--new-ratio）/ init-from model_104.npz / lr 1e-4 / 780step固定
判定: vs 104 直接（n=1200・CRN）+ プールv6.1
```
EXP-114 で整備した枠組みをそのまま使う。
