# EXP-139: 貼り先/進化先の「正体」を opt_enc に入れる — 再構成できた時点で冗長だった

- 日付: 2026-08-16
- 対象: L1（1層LSTM・正規化なし、219系）に対象カード埋め込みを追加（+2,048パラメータ）
- 状態: **棄却**。狙い所の部分集合で **−0.03pt**（3シード、sd 0.59pt、t=−0.10）

## 1. 仮説

pointer network の選択肢塔 `opt_enc` は、選択肢の**対象**について
`inPlayArea`/`inPlayIndex`（位置）と `_inplay_target_feats` の**残HP比・エネ数の2次元**しか持たず、
**種族が入っていない**。MAINでは `cls_head` の65クラスが `ATTACH_BUCKET` で代役をするが、

```
ATTACH_BUCKET = {741:'abra_p', **742:'abra_p'**, 743:'abra_f', 305:'dunsparce_p', ...}
                          ↑ Abra と Kadabra が**同一クラス**
```

粗い。しかも ctx37 EVOLVE は非MAIN（`opt_cls = -1`）なので `cls_head` 自体が効かない。
→ **対象の正体を opt_enc に一元化すれば、cls_head が割れない決定を pointer が割れるはず**。

## 2. ★ スコープの測定（教師435,150決定）

途中で**2つの誤りを自分で訂正した**（どちらも測定で判明）。

| | 初期の主張 | 実測 |
|---|---|---|
| Boss's Orders のガスト先 | 正体が落ちている | **落ちていない**。ctx3 SWITCH は**選択肢そのものが対象**で `opt_cid`→`card_emb` に入る |
| 非MAINの対象あり選択肢 | 73,386 | **11,836**（ctx37のみ） |

**`inPlayArea = 0` は AreaType に存在しない「対象なし」の番兵**だった。
ctx 7/5/2/19 に61,550件あり `ipi` は常に0、`_inplay_target_feats` は**全件 [0,0] を返している**。
`ipa >= 0` でフィルタしていたため対象と誤カウントしていた。正しくは `ipa ∈ {ACTIVE, BENCH}`。

```
対象を持つ選択肢              953,577 = 全実選択肢の **25.9%**
うち対象が一意でない(MAIN)    244,524 = MAIN対象ありの **26.0%**
ctx37 EVOLVE（cls_head 無効）  11,836
→ 対象の正体が未表現           **256,360 = 全体の 7.0%**

MAIN決定 269,634 のうち「同一 abra_p クラスに2個以上の選択肢」 **59,456 = 22.1%**
うち教師が実際にその曖昧クラスから選んだ決定                    **7,125 = 2.6%**
```

## 3. 実装（再抽出なしで作った）

**`board` の `ms{slot}_{種族}` が自分スロットの厳密な one-hot**（featgen_core.py:739）で、
`my_list = [active] + bench`、`_inplay_target_feats` は必ず自分の場を見る。よって

```
slot = 0        if inPlayArea == ACTIVE
     = ipi + 1  if inPlayArea == BENCH
対象カードID = ms{slot}_{種族} の立っている種族
```

で**既存 npz から復元できる**。検証は 953,577選択肢すべてで

```
種族one-hot 1本  **100.0000%**
エネ枚数一致     **100.0000%**  （ms{slot}_e  vs opt_vec[25]）
HP比一致         **100.0000%**  （ms{slot}_hpr vs opt_vec[24]）
```

**train/inference skew の直接検証**も実対局で通した（推論側 `option_target_cid` は obs から直接引く）:

```
8試合 / 選択肢 6,484 / 対象あり 1,572 (24.2%) / **不一致 0**
```

**cls_head では割れず pointer 内積が正解を決めた**決定（val 6,011件 = MAIN の25.4%）。
全体valでは該当が1.6%なので差が埋もれる。

| seed | te | base | 差 |

事前登録どおり**プールは回さずに棄却**した。

## 6. ★ 機序: 再構成できた時点で冗長だった

**学習ラベルを `board` + 位置から 100.0000% の精度で復元できた、という事実そのものが
「その情報はネットワークの入力に既に在る」ことの証明になっている。**

```
board    ms{0..5}_{種族} の one-hot（自分の全スロット）  ← 状態塔が持っている
opt_vec  inPlayArea / inPlayIndex（どのスロットか）      ← 選択肢塔が持っている
```

対象の正体は**欠けていたのではなく、2つの塔にまたがって分散していた**。
`q` が「スロット1を指す方向」を作り、`h` が「スロット1にKadabraがいる」を知っていれば、
内積で合成できる。今回の追加は、その合成を**選択肢塔の中に前倒ししただけ**で、
新しい情報は1ビットも入れていない。

補助的な事実として、狙い所の部分集合は**ベースで既に 0.808**（全体0.873に対して低い＝
伸びしろ19%は実在する）。**伸びしろはあるが、それは対象の正体を知らないことが原因ではない。**

## 7. 教訓

> **特徴を足す前に「既存の入力から復元できるか」を確かめる。
> ラベルを作るために自分で復元できてしまったなら、ネットワークにも復元できる。**

これは EXP-120（棄却済みの軸Aが9本の特徴器に自動混入）や
EXP-133（prev_opp、プール −0.65pt）と同じ「入力追加系」の系譜で、**4連敗目**。
入力追加の打率が悪い理由が今回1つ特定できた: **既存特徴が十分に細かいと、
「足りない」と見える情報の多くは実際には導出可能**。

**two-tower の分業に穴があるように見えても、それが「情報の欠落」なのか
「因数分解のされ方」なのかを区別すること。**後者なら内積が合成してくれる。

## 8. 副産物（残す）

- `--eval-only`（`--init-from` と併用）: 学習せず保持データの指標だけ出す。
  分割・標準化・語彙が学習と同一コードを通るので手で再現しなくてよい
- **クラス同点決定の一致率**を val 指標に追加（`_tie_*` / `_tiec_*`）。
  「cls_head では割れない決定」を直接見られる。ベース実測:

| モデル | val | MAIN | 正解クラス同点 |
|---|---|---|---|
| 186 (L2) | 0.8706 | 0.8340 | 0.8075 |
| L1 3seed平均 | 0.8726 | 0.8375 | 0.8069（sd 0.21pt） |

- `opt_tcid` の**指紋照合**（別の train.npz から作った添付を黙って載せない）
- `max_game_len` の外れ値除去キー列に新規配列を入れ忘れると**そこだけ行がずれて無言で壊れる**
  （今回1度踏みかけた。派生配列を足すときは必ずこの列を確認する）
