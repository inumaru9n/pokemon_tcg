## 結論

1. **オフラインとアリーナが違う話をしている**。オフラインは「データとハイパラが半々」と言うが、
   アリーナは「**データ効果ゼロ / ハイパラが全部**」と言う。
   一致率の増分は、それがどの要因から来たかも、アリーナに転移するかも教えてくれない。
   **「agreement ⊥ arena」の最も明快な実例**（同一の+0.85ptが、片方は0pt、片方は+1.8ptに化けた）
2. **部分の和が全体に届かない**: 0 + 1.8 = 1.8pt に対し、実測の全体は +3.17pt。
   CIの範囲内ではあるが、素直に読めば「個別には検出できない効果の合成」、
   疑って読めば非推移性（EXP-070/072で観測済み）。現在の戦数では区別できない
3. **I-112（日次再学習）の前提が揺らいだ**。EXP-058は「日次再学習は改善でなく保守として
   毎日回す価値がある」と結論したが、根拠は052ベースの一致率減衰という**オフライン観測のみ**で、
   データ更新の効果をアリーナで単独測定したことは一度もなかった。**本EXPが初の単独測定で結果はnull**。
   限定: 今回の更新は1日分(+28%)にすぎず「1日追加では効かない」と「日次再学習に価値がない」は別。
   ただし日次運用の1サイクルがまさにこの1日追加なので、運用の正当性に直接刺さる

4. **EXP-070の「validated」は偽陽性の可能性が高い**。全ペア・全プールを揃えた結果、
   058 ≈ 073 ≈ 074 ≈ 070 が区別できない。それなら070 vs 058 も50%のはずだが実測は
   0.5317 [0.5070, 0.5562]。CI下限が50.70とギリギリで、**本セッションで多数の比較を
   行っている以上、1つ閾値を越えるのは十分あり得る**（多重比較）。
   最も妥当な読みは「**4モデルすべて同じ強さ**」であり、070の改善は実在しなかった
5. **モデル側のチューニング軸は全て空**: データ+1日 / lr / num_leaves / min_data_in_leaf /
   アンサンブル(EXP-071) / 管轄拡張(EXP-072) / ルール矯正(EXP-069) — **どれもアリーナ効果ゼロ**。
   現アーキテクチャ上の改善余地は尽きた
6. **実務的な収穫: 073は070の1/8のモデルで同等**（5,735木/5.4MB vs 47,767木/21.8MB）。
   同じ強さなら軽い方が本番の時間予算に余裕を生む。提出物としては073系が優位

## 副産物の訂正（本EXPで判明した過去の誤り）

1. **058は rounds固定ではなく early stopping を使っていた**（patience=80、best_iter=121）。
   EXP-070の記述を訂正済み
2. **EXP-070はグリッド選定をtestで行い同じtestで報告していた**（選定バイアス0.13pt）。
   正しい値は0.7754。訂正済み。アリーナ値は独立測定なので無傷
3. **手番時間の比較が無効だった**: `main.py` は `.txt`(lightgbm) があればそれを優先し、
   無ければ `.npz`(純Python) を使う。073の「5.5ms」はlgbモード、072の「90ms」はnpzモードで、
   **比較になっていなかった**。npz同士の比較は未測定
4. **提出済み072のnpzパリティを検証**（EXP-070では木が多すぎてタイムアウトし省略していた）:
   **800/800 = 100%一致**、129.6ms/推論。1ゲーム約100決定として13秒＝600s予算の2%で問題なし
