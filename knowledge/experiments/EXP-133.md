# EXP-133: 相手の直前の選択を入力に足す（prev_opp）— 棄却

- 日付: 2026-08-14
- 対象: 入力に**相手が直前に選んだカード**（`prev_card_emb` 共有 + 数値2）を連結
- 状態: **棄却**。プール **−0.65pt**

## 1. 動機

186 は `prev`（**自分の**直前の選択）しか見ていない。
「相手が直前に何を出したか」は盤面（`opp_seen_*` / `dis_*`）に痕跡が残るが、
**順序と直近性**は落ちている。カードゲームでは直前の1手が最も情報量が多いはず、が仮説。

## 2. 実装

```
d_in = n_board + n_logs + 16 + d_card + 2 + **(d_card + 2)**   ← 559 → 593
```

- `prev` が **6要素の npz でのみ有効**（3要素なら従来と厳密に同じ次元になる）
- **`prev_card_emb` を共有**する（「誰が使ったか」は別の数値で区別し、
  カードの意味自体は共有する）
- 語彙は無条件に足すと +99語になり、その大半が基本エネ（色は `os*_et*` に既出＝冗長）と
  数百回未満の稀少札。**教師データに乏しい札を足すと他の学習を薄める純損失**になる
  （EXP-120 で −2.29pt を実測）ので、2条件で絞った:
  ① **非冗長性** — identity が `opt_vec` の数値特徴を超える情報を持つか（"Basic " 除外）
  ② **学習可能性** — 出現数 >= 10 × d_card = **320回**
  （board列の 10×d_model=2,560 とは**別の閾値**。埋め込み1行は32パラメータであって256ではない）

## 4. 機序

**情報が既に入っていた**、が最も素直な説明。

```
「相手が何を見せたか」   → **opp_seen_***（79次元）
「何が捨てられたか」     → **dis_***
「前回決定以降に何が起きたか」→ **logs 48次元**（LogType別カウント、自分24 + 相手24）
```

`logs` は**前回の自分の決定以降**を集計しているので、
「相手が直前に何をしたか」は既にそこに含まれている。
追加したのは**カードの identity と順序**だけで、それは +34次元の希釈に見合わなかった。

## 5. 位置づけ

**入力追加系の1敗目。**この後 LayerNorm（EXP-134）、対象カード埋め込み（EXP-139）と続き、
EXP-139 で共通の機序が特定された:

> **特徴を足す前に「既存の入力から復元できるか」を確かめる。**

prev_opp はこの検査を通していれば（`logs` と `opp_seen_*` から近似的に復元できる）
着手前に落とせた可能性が高い。
