## 結論

**階層の合成形を変えても改善しない。現行の additive を維持する。**

| head | val s1 | val s2 | val平均 | MAIN s1 | MAIN s2 | MAIN平均 |
|---|---|---|---|---|---|---|
| **additive（現行）** | 0.8633 | 0.8629 | **0.8631** | 0.8312 | 0.8296 | 0.8304 |
| maxpool | 0.8621 | 0.8635 | 0.8628 | 0.8311 | 0.8320 | **0.8316** |
| factorized | 0.8605 | 0.8627 | 0.8616 | 0.8275 | 0.8283 | 0.8279 |

- **additive vs maxpool は判別不能**: val差 0.0003 / MAIN差 0.0012 に対しシード幅が 0.0004〜0.0014
- **factorized のみ一貫して劣る**: MAIN一致率の最大(0.8283) < 他形式の最小(0.8296)。
  ただし差は 0.25pt と小さい。**アリーナのノイズ床（n=400でCI±5pt）の遥か下なので対戦検証はしない**

## 何を比べたか

MAIN選択肢のスコアは2項の和 `A(pointer) + B(クラス点)`。クラス内分布はどの形も
`softmax_{j∈c}(A_j)` で同一で、違うのは `P(クラス)` の logit だけ。

| head | `P(クラス)` の logit | 選択肢の質を見るか | 選択肢の数に影響されるか |
|---|---|---|---|
| additive | `a_c + logsumexp_{j∈c}(A_j)` | ✅ | ❌ 個数で膨らむ |
| maxpool | `a_c + max_{j∈c}(A_j)` | ✅ | ✅ 無関係 |
| factorized | `a_c` | ❌ | ✅ 無関係 |

## 事前に自分の主張を訂正した経緯（重要）

当初「加算形は階層分解を表現できないので factorized に変えるべき」と主張したが、
**式変形で加算形が既に階層分解であることが分かった**:

```
P(i) = exp(A_i + a_c) / Σ_j exp(A_j + a_c(j))
     = [exp(a_c + LSE_c) / Σ_c' exp(a_c' + LSE_c')] × [exp(A_i) / exp(LSE_c)]
       = P(クラス)                                    = P(選択肢|クラス)
```

**加算形とは「クラスlogitに `logsumexp_{j∈c}(A_j)` が入った階層モデル」**であり、
私が「歪み」と呼んだ項は**選択肢の質の信号でもあった**（片面しか見ていなかった）。
実装後、`additive` と `logsumexp`（明示的に LSE を足す形）の val が
**完全に一致**（0.5539160045402951、小規模検証）したことで式変形が裏付けられた。

さらに実測で **MAIN決定内のクラスは77.3%が選択肢1個**と判明。純factorizedだと
そこで `P(選択肢|クラス)=1` となり **pointer（カード埋め込み+28次元の選択肢特徴）が
完全に無視される**。「悪化するはず」と事前予測し、実測でそのとおりになった。

**教訓: 「理論上こちらが正しい」で構造を変える前に、データ側の分布（クラスあたりの
選択肢数）を先に見る。** 77.3%が1個という事実だけで結論は出せた。

## 副次的に測れたノイズ床

EXP-097 の `d20`（seed=1, additive, 同一設定）は val 0.8646、本実験の `additive_s1` は 0.8633。
差 0.0013 の原因は**標準化統計の計算法をチャンク化（float64和 / tr_idxをソート）した数値差だけ**。
**数値的に無視できる変更でも val が 0.13pt 動く**＝この指標の実効ノイズ床は約0.15pt。
0.1pt級の差を「改善」と読んではいけない。

### 実装中に見つけた穴

**① torch.where 経由で逆伝播にNaNが伝播する**

非MAIN決定では `opt_cls=-1` が `ci=0` にクランプされる。クラス0にその決定の選択肢が
1つも属さないと `m_c=-inf` となり `exp(-inf −(−inf)) = NaN`。forward は `torch.where` で
潰せるが、**`torch.where` は選ばれなかった枝のNaNも逆伝播で伝播させる**。
指数に入る前に `nan_to_num(m_c, neginf=0.0)` で丸めて解消。4形式で勾配が有限であることを
テストで確認した。

**② エージェント配下の `nn_102.py` が旧版のままだった**

`tools/featgen_nn.py` を更新したのに複製し忘れ、`maxpool`/`factorized`/`logsumexp` で
**torch と単発numpy が最大 4.66 ズレていた**（バッチ版は一致）。
`selfplay/check_export.py` が検出。修正後は4形式すべてで3経路が ≤9.5e-7 で一致。
