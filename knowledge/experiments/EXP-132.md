# EXP-132: ExIt の全軸を閉じる — ラベル品質は一致率を倍にするが、勝率は下がる

- 日付: 2026-08-13〜08-14
- 対象: 186 を初期値とする ExIt 蒸留（生成 3,900試合・23,379局面）
- 状態: **棄却。ExIt はこのゲームでは成立しない**（量・質・質×量・推論時探索の4軸すべて）

## 1. 経緯

EXP-124（補正1,089件）で「暗記のみ」、EXP-125（推論時探索）で「隠れ情報を推測すると
価値が消える」と結論した。EXP-130 で**量**を 2,557件に増やしても保持一致率は 9.2%→9.3% で
動かず、**天井は観測可能性にある**と報告した。

**その報告は早計だった。** ユーザの指摘（学習データの選別）を受けて**ラベルの質**を測ると、
教師行の9割がノイズであることが判明した。

## 2. ★ ラベル品質の測定（CRNペア符号検定）

`R`（候補×M）は**全候補が同一の search_begin から分岐**しているので列ごとに対応がある。
best列 vs top1列 で符号検定できる。

```
全2,557件            不偏gap **+0.0813**
q差 >= 0.10  1,376件  +0.1734
**p<=0.20**    610件  **+0.3005**
**p<=0.05**    265件  **+0.4360**   ← 全体平均の **5.4倍**
```

**厳密な検定を通るのは10%だけ**で、残りは「24本回して偶然 best が入れ替わっただけ」。
それを全部同じ重みで教師にしていた。EXP-130 で量を増やしても動かなかったのは、
**増えた分もほとんどノイズだった**ため。

## 3. ★ 選別は一致率を倍にした（同一保持集合での比較）

| モデル | 高品質補正 | 全補正245件 | 高品質64件 |
|---|---|---|---|
| 186（ベース） | — | 0.0% | 0.0% |
| EXP-130 全件 | 2,557 | 9.0% ±3.6 | 12.5% ±8.1 |
| **A 選別** | **610** | **16.3% ±4.6** | **39.1% ±12.0** |
| C 選別（増量） | 1,130 | 15.1 / 17.1% | 32.8 / 37.5% |
| B 全件・重み付け | 2,557 | 9.4% ±3.7 | 14.1% ±8.5 |

- **硬い選別（捨てる）が最良**。B（弱いラベルを小さい重みで残す）は効かない
  ＝ **重みを下げてもノイズは勾配に入り続ける**
- **A は610件しか学習していないのに、学習していない残り1,947件を含む全補正でも最良**（汎化）
- **質×量は頭打ち**: 610 → 1,130件（1.85倍）で 16.3% → 16.1%（2シード平均）

## 5. ★ 機序: 0.25回/試合を直すために80回/試合を歪めている

```
補正の発火頻度      **1試合あたり 0.2〜0.3回**（M=24到達局面の一部）
MAIN一致率（186の再現度）  186 0.93 → A 0.923 → C 0.917〜0.925
```

**方策全体をわずかに歪めて、ごく稀な局面を直している。** しかも直せた補正は
EXP-125 が示すとおり**賭け金の小さい局面に偏る**（推測探索は乱択超えの信号の42%を拾うのに
gapは2%しか取れなかった）。差し引きで負ける。

> **教訓: 「教師の再現度」と「強さ」は同じ方向に動くとは限らない。**
> 模倣学習では一致率↑＝強さ↑だったが（090→092で対壁+9.75pt）、
> **ExItの補正は発火頻度が低すぎて、その関係が反転する**。
> **発火頻度 × 効果量 が、方策全体を触る代償を上回るかを先に見積もるべきだった。**

## 7. 実装上の事故と対処（再現性の記録）

- **指紋はバッチをまたぐと衝突する**: 序盤の定型局面は別の試合でもビット一致しうる
  （2バッチ合算で多重ヒット927件、バッチ単体では0件）。**索引をバッチごとに分けて解決**
- **Kaggleのdataset作成は非同期**: `dataset` の直後に `kernel` を投げると
  `/kaggle/input` が空のまま起動して `train.npz not found` で落ちる。
  **`datasets status` が ready になるまで待ってから kernel を投入する**
- **チェックポイントのstep番号はデータ量で変わる**: `_n_ep = round(max_steps/_spe)` なので
  データが増えると最終stepが1,600に届かない（Cは1,575で終了）。`_final` を使う
