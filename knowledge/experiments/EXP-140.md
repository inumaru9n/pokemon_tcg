# EXP-140: LSTM を丸ごと外す — val は大勝ちしプールは負ける

- 日付: 2026-08-16〜17
- 対象: L1（1層LSTM・正規化なし、222の構成要素）から **LSTM を除去**（788,995 → **262,659**）
- 状態: **棄却**。val +0.62pt（t=12.4）に対し、プール **−1.16pt**（対 222）

## 1. 仮説

深さの実測は **L1 0.8718 > L2 0.8703 > L3 0.8696 > L4 0.8682** と単調だったが、
**L0 は一度も測っていなかった**。LSTM は 1,052,672 パラメータ＝全体の80%。

しかも「LSTMが持っている」と思っていた履歴の多くは、**盤面特徴が既に持っている**:

```
「Rare Candy を使い切った」  → **pool_1079**（山∪サイドの残り枚数）
「何が捨てられたか」          → **dis_***
「相手が何を見せたか」        → **opp_seen_***
「前回決定以降に何が起きたか」 → **logs 48次元**
```

DeNA/HandyRL も**ステートレス**Transformer で 96.2% を出している（knowledge/discussions）。

## 2. ★ 設計: 再帰と深さを分離する

LSTM の除去は *再帰* と *深さ2層分* を同時に消すので、単独では交絡する。3水準を置いた。

| 構成 | 中身 | パラメータ |
|---|---|---|
| base | L1（現行ベストの構成要素） | 788,995 |
| **l0** | 再帰なし（enc → proj 直結） | **262,659** |
| **l0m** | 再帰なし + MLP 2層（深さは保つ） | 394,243 |

**同一 Kaggle run の中で交互順**（l0_s1 / l0m_s1 / base_s1 / l0_s2 / …）に9本。
データ・前処理・系列順・ハイパラが完全一致し、**差は `layers` の値だけ**になる。

## 3. ★ 学習の結果: L0 が明確に勝つ

| 構成 | val（3シード） | MAIN | 訓練-検証差 |
|---|---|---|---|
| base L1 | 0.8692 / 0.8709 / 0.8687 → **0.8696** | 0.8372 | **+0.0475** |
| l0m | 0.8697 / 0.8715 / 0.8705 → 0.8706 | 0.8384 | +0.0113 |
| **l0** | **0.8763 / 0.8763 / 0.8747 → 0.8758** | **0.8460** | **+0.0106** |

```
l0 − base   val **+0.62pt**（3シードとも同符号、sd 0.086pt、**t = 12.4**）
            MAIN **+0.88pt**（t ≈ 20）
l0m − base  val +0.10pt   ← **ほぼ無し**
```

**機序は過学習**（訓練-検証差が **4.5分の1**）。教師は 5,309試合 / 435,150決定しかなく、
789k〜1.3M パラメータは多すぎた。

**効いたのは「再帰を外したこと」ではなく「容量を削ったこと」**。
131k の MLP を足し戻した l0m は利得の 84% を失っている。

## 5. 教訓

> **val の差が大きく有意でも（t=12.4）、プールの符号は保証されない。**
> LayerNorm（val +0.42pt → プール −0.94pt）と同型のパターンが、
> **効果量が桁違いに大きいケースでも再現した**。

過学習が減って教師の再現度が上がることと、対戦で強くなることは別。
EXP-132 の「教師の再現度と強さは同じ方向に動くとは限らない」の、**容量側からの実例**。

## 6. 実装上の記録（再現性）

- **推論の numpy 実装を必ず torch と突合する**: `check_export.py` は
  `d_model` を `lstm.weight_hh_l0` から取るため **L0 で KeyError**。提出経路
  （agent_dir の `nn_*.py`）だけを照合する検証を別に書いた。結果は
  **最大差 7.629e-06 / argmax不一致 0**（91決定）
- `nn_*.py` の L0 対応は2箇所。`n_layers` は元から `lstm.weight_ih_l*` のキー数で
  数えているので、**既存の L1/L2 モデルの挙動は変わらない**
- **★ プール評価は `--pool` を明示する**: 既定の `arena/pool.json` は更新されており、
  上位2枠が新しいSLレプリカ（176_marnie_clean / 174_alakazam_clean、**合計49.1%の重み**）に
  差し替わっていた。過去の数値はすべて `pool_v7.json`。既定のまま回すと
  **errors=0 のまま黙って別の相手と戦い、比較不能な数字が出る**（実際に踏んだ:
  239 が 64.58% と出て −8.68pt の「大敗」に見えた）
- **cuDNN の LSTM はビット単位の再現性が無い**: 同一シード・同一データ・同一ハイパラでも
  base の val が run 間で **約0.1pt** 振れた（EXP-139 の base 0.8705 vs 本 run 0.8696）。
  L0 は LSTM を持たないのでこの非決定性自体が消える

## 7. 副産物（残す）

- `PolicyNet(n_layers=0, post_mlp=k)`: 再帰なし / 再帰なし+MLP。**既定は従来と同一**
- `--eval-only`（`--init-from` と併用）: 学習せず保持データの指標だけ出す
- **クラス同点決定の一致率**（`_tie_*` / `_tiec_*`）: cls_head では割れない決定の一致率
- エージェント 236/237/238（L0単体）/ 239（L0×3）。**239 のみプール測定済み**
