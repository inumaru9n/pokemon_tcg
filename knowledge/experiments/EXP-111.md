# EXP-111: 相手の隠れ情報の推論（軸A）+ focal loss（軸C）— 標準化の分布外爆発を発見

- 日付: 2026-08-06
- ベース: 117_alakazam_dspline（デッキ・教師・期間すべて同一。**特徴器だけが違う**）

## 動機: 情報の非対称

方策のブレイクスルーを軸ごとに洗った結果、**情報の使い残し**が1つ見つかった。

```
自分側: left_/pool_ 22枚 + 超幾何確率（p_psy_all_prized）  ✅
相手側: opp_seen_*（観測した生カウント）のみ               ❌
```

**相手のアーキタイプは96%の精度で識別できている**（oparch_*）のに、
「アーキタイプが分かれば60枚は既知」という事実を使っていなかった。
「相手のBoss's Ordersはもう0枚」「Unfair Stampを持つ確率は35%」は
ベンチの置き方・手札の抱え方を直接変える情報で、**モデルには計算できない**
（デッキ構成という外部知識と超幾何分布が要る）。

## 実装

### tools/gen_meta_cards.py（新規）

従来は `featgen_core.py` にメタ知識が**直書き**で、**07-22メタのまま固定**されていた
（Mega Lopunny ex 9.7% と Teal Mask Ogerpon ex 7.2% が欠落）。再生成可能にした。

| | 旧 | 新 |
|---|---|---|
| META_CARDS | 52枚 | **81枚** |
| oparch_* | 7系統 | **9系統** |
| ARCH_DECK（各系統の60枚） | — | **新設** |
| OPP_TRACK（追跡カード） | — | **20枚**（Boss's Orders・Unfair Stamp・全系統の主戦力） |

### 特徴（506 → 563次元、+57）

```
opp_left_{cid}   ×20   相手の山にあと何枚（ARCH_DECK − opp_seen）
opp_phand_{cid}  ×20   **手札にある確率**（超幾何: 1 − C(n−k,h)/C(n,h)）
opp_arch_conf / margin / known、opp_unseen_n、opp_hand_n、opp_main_left / phand
```

実測（vs Marnie 906決定）: アーキタイプ推定96.5%正解 /
**相手がBoss's Ordersを持つ確率 平均20.1%・最大51.7%** / Grimmsnarl ex が山に平均2.28枚。

### focal loss（軸C）

当初案の「強制手を落とす」は**学習に無影響**と判明（選択肢1個は softmax が1点＝CE=0・勾配ゼロ）。
代わりに focal loss（正解の予測確率が高い決定の重みを下げる）を実装。γ=0 で従来と厳密一致。

## ★ 発見したバグ: 標準化の分布外爆発

学習は正常に完了したが（val 0.8641 / 0.8657、104の0.8646と同水準）、対戦で矛盾が出た。

```
132 vs 117 直接      54.2% [51.4-57.1]  ✅有意に強い
132 プール加重        −3.43pt            ❌有意に劣る
```

対面別を見ると **対Ogerpon だけが 78.2% → 30.7%（−47.6pt）** と壊滅していた。
他の4体（104/117/128/129）は全て69〜78%で正常なので、**563次元の新特徴器に固有**。

標準化後の値を測ると:

| 対面 | \|z\|平均 | 最大\|z\| | 最悪の特徴 |
|---|---|---|---|
| **Ogerpon** | 2.609 | **2000.0** | **opp_seen_1251（Lively Stadium）= 744σ** |
| Marnie | 0.573 | 12.0 | opp_left_648 = 1.3σ |
| Lopunny | 0.719 | 29.7 | opp_seen_848 = 13.5σ |

**機序**: META_CARDS を新メタで再生成して81枚にした一方、**教師データは旧メタ（07-17〜29、
Ogerponが存在しない期間）のまま**。訓練中ずっと0だった特徴は標準化の sd が下限（1e-3）に
張り付き、本番で値が入ると桁外れのσがネットワークに流れ込む。

### 対処: 標準化後のクリップ（±10σ）

**学習側（`train_nn_kaggle.py` の `_apply`）と推論側（`tools/featgen_nn.py` の board/opt 両方）
に入れ、npz の `norm_clip` で共有する**。既存モデルには後付けした（訓練時クリップ無し・
推論時のみだが、744σは訓練中に一度も見ていない値なのでクリップした方が訓練分布に近い）。

```
対Ogerpon（n=400・同一CRN）
   132   30.7% → **76.5%**  (+45.8pt)
   133   27.1% → **80.2%**  (+53.1pt)   ← 117の78.2%を上回る
```

## 教訓

**メタ知識を更新したら、教師データの期間との整合を必ず確認する。**
特徴を増やすこと自体は安全に見えるが、**教師データに現れない特徴は標準化を通じて
分布外の入力になる**。これは例外を出さず、val一致率にも現れず（val は教師と同じ期間なので）、
**新メタの相手と当たったときだけ方策が壊れる**。

この修正は今後の全モデルに効く。メタが動くたびに同じ事故が起きる構造だった。

## 結果: **判別不能**（クリップ適用後）

| | vs 117 直接 | プールv6.1 加重差 |
|---|---|---|
| **133**（軸A + focal γ=2） | **51.3%** [49.7-53.0] n=**3600**（2シード合算） | seed05 **+1.18** / seed06 **−0.42** |
| 132（軸Aのみ） | 53.6% [50.8-56.4] ✅有意 → 53.6/54.2%で再現 | −0.12pt |

**エンジンシードを変えると符号が反転した**（+1.18 → −0.42）。
対面別でも Marnie（w48.3）が +2.1 → −1.7 と反転しており、
**重み最大の枠が振れると総合が振れる**。単一シードの +1.18pt を改善と読んではいけない。

132 は直接対戦で2回とも有意（53.6% / 54.2%）だが、プール加重では −0.12pt。
**直接対戦（Alakazamミラー）とプール加重は別の量**（CLAUDE.md「直接対戦は非推移」）。

## ★ 行動は意図どおり変わっている（機序の確認）

軸Aが効かなかったのは「特徴が無視された」からではない。実測（vs Marnie、MAIN決定）:

| 相手がBoss's Ordersを持つ確率 | 決定数 | 133と117の不一致率 | 自分のベンチ平均 |
|---|---|---|---|
| 低 (<0.2) | 421 | 9.7% | 3.22 |
| 中 (0.2-0.5) | 676 | 15.8% | 3.46 |
| **高 (≥0.5)** | 69 | **23.2%** | **2.70** |

**相手がBoss's Ordersを持つ可能性が高いとき、133は2.4倍の頻度で違う手を打ち、
ベンチを0.5〜0.8体少なく保つ。** Boss's Orders は相手のベンチを引きずり出す札なので、
これは理にかなった防御。

**しかし勝率には出なかった。** 「正しい情報を与え、方策が意図どおり反応しても、
勝率が動くとは限らない」＝EXP-105（打点0の攻撃を禁止）と同じ構図。
