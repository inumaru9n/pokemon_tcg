# EXP-090: 089_marnie_ml + lethal限定決定化探索層（075式3層化: lethal→ML→ルール）

- 日付: 2026-07-25
- BACKLOG: I-135
- エージェント: `agents/090_marnie_ml_lethal/`（=089の完全コピー + 043のlethal層移植。deck=1ec0f47981）
- 状態: **validated**（改良系基準: (a)ベース089直接CRN 400戦 55.75%[50.8-60.5]でCI下限>50の
  有意勝ち越し (b)狙いのlethal発火ゲーム勝率220/221=99.5%。プールv4 weighted 64.5%[61.6-67.4]、
  全評価errors=0）

## 仮説

089（082ルール背骨+MAIN行動クラスGBT層、EXP-089）にlethal限定決定化探索を最上層として重ねれば
（075式の3層構成）、ML層が残す「確定勝ちの見逃し」を刈り取り、ベース089に非劣化で発火ゲームを
ほぼ全勝できる。lethal層は評価関数を使わない（全決定化サンプル勝利のみ上書き）ため、
構造上ベース同等以上（EXP-007の設計原則）。

## 方法

### 実装（agents/090_marnie_ml_lethal/）

- **089の完全コピー**+ヘルパーを090へリネーム（feat_090.py / attack_table_090.py /
  model_090.npz / model_090.txt。**089と090が同一対戦で同時ロードされるためモジュール名衝突回避が必須**）。
  学習スクリプト（collect/train/export）はコピーせず089を正とする（モデルは同一バイナリ）
- **lethal層は043_marnie_full（EXP-043）から移植**: `_determinize`（自デッキ消去法+悪エネパディング、
  相手はプレースホルダ基本ポケモン）、`_lethal_search`（自分サイド≤3のMAIN単一選択のみ・上位8候補×
  8サンプル・全サンプル勝利のみ上書き）、`_rollout`（自ターン終端までルール方策でグリーディ再生）。
  SEARCH_SAMPLES=8（EXP-043: Marnieは手中ドロー線が多く5では敗北オーバーライド3/300→8で1/300）
- **プラン汚染対策（EXP-043の必須修正、INSIGHTS準拠）**: 038系背骨はグローバル`plan`を
  インプレース変異するため、探索ロールアウトが実対局のサブ選択（Boss吊り先/エネ貼り先/リトリート先）を
  汚染する。agent()でMAINスコアリング直後に**planの値スナップショット**を取り、探索後に復元。
  計装のカウンターファクチュアル計算後も再復元
- **_search_time_usedのリセットはagent()冒頭**（turn≤2で0.0）。043の探索関数内リセットは
  プライズゲート（>3で即return）が先に走るため実際には発火しない潜在バグ（045と同型、INSIGHTS）で、
  ここで修正した形を採用
- **層順**: lethal（発火時は即return）→ ML（089と同一）→ 082ルール。`F090_LETHAL=off`で層を無効化
  でき、探索API不可環境では例外→Noneで自然フォールバック（007と同じ構造）
- 時間予算: 1.5s/手 + ゲーム累計450s（<600s本番制限）。全て043と同値
- 計装: `F090_STATS`（search_calls/fires/overrides）を本体に常設（コスト=カウンタのみ）。
  発火ゲーム別集計は `agents/090_marnie_ml_lethal/instrument_090.py`（in-processでrun_match.play_gameを
  再生し、ゲーム間でカウンタ差分を読む。play_gameはgame_indexごとに決定的なので公式CRN対戦と同一ゲーム列）

### 検証手順

1. スモーク: vs 000_random 20戦 → 20-0、errors=0
2. **同一挙動チェック（CRN）**: `F090_LETHAL=off`の090 と 089 を vs 000_random 20戦
   （--engine-seed 7777）で比較 → **全20レコード（winner/steps/reason）完全一致**
3. 本ゲート: vs 089 直接400戦（--engine-seed 1350001、-w 2）+ 同条件のin-process計装400戦
4. プールv4: n=200×8、seed 42、-w 2

### 発火計装（同一400ゲームのin-process再生）

- 探索実行 4,176回 / 発火（全サンプル勝利の上書き返却）1,551回 / うちML・ルール層の選択と
  異なる真のオーバーライド 706回（203ゲーム）
- **発火ゲーム 221 / 勝ち 220 = 99.5%**（前例: 043=97.5%、EXP-075系=99.1%と同水準）。
  敗北発火は game 195 の1件のみ（≈0.5%、SAMPLES=8の既知残存率）
- 非発火179ゲームの勝率 4/179（発火≈「勝ち切り局面に到達した」の標識。ミラーCRNでは
  勝敗の因果は+5.75ptの差分側で読む）
- 注意: 探索は壁時計デッドラインを持つため**厳密には決定的でない**（同一CRN 400戦の再実行で
  223勝/224勝の±1ゲーム揺れを観測）。CRNペアの解釈には影響しない規模

## 結論

- **validated**。lethal限定探索のML背骨への移植3例目（036ルール→043精読ルール→090 ML）が成立。
  **「lethal層は背骨の種類に依存せず+5pt級を積む」**ことをCRN直接対決で確認
  （043のとき: 038系+lethalで対038直接53.75%。090: 089+lethalで対089直接55.75%）
- EXP-043のプラン汚染バグ対策（値スナップショット）と_search_time_usedのagent()冒頭リセットを
  最初から織り込み、スモーク→CRN同一挙動→本ゲートまで手戻りゼロ。**F090_LETHAL=off時の
  089完全一致（CRN 20戦全レコード）を確認済み**=移植の分離性が保証された形
- プールv4 64.5%は**プールv4計測で現時点最高値**（089=59.7%、075系はv4未計測のものあり。
  親のladder A/B判断材料として提出候補に足る）
- INSIGHTS昇格候補:
  - 「lethal限定探索層はルール背骨だけでなく**ML背骨（行動クラスGBT）にもそのまま積める**。
    089+lethal=090は対089直接CRN 400戦55.75%[50.8-60.5]、発火ゲーム勝率99.5%（EXP-090）。
    移植チェックリスト=①ヘルパーのモジュール名リネーム（同時ロード衝突）②plan値スナップショット
    ③_search_time_usedはagent()冒頭リセット（043/045の探索関数内リセットはプライズゲートが
    先に返るため死にコード）」
- 派生アイデア（BACKLOG追記は親に委任）:
  - 090のテールスポットチェック（042 Crustle等。089は41%が唯一の穴=lethalでの上積みを確認する価値）
  - 089の非MAIN学習層（EXP-089残課題）が入った場合の090再ゲート（層は直交なので同モデル差し替えで可）
  - プールv4のMarnie枠を090系へ交代する案（EXP-089派生案と同じ論点+探索の非決定性・速度に留意）
