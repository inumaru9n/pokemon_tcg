## 発見した実装の穴（いずれも実害あり）

### ① Alakazamの主砲の打点が構造的にゼロだった（最重要）

`attack_table_056.py` は EN_Card_Data.csv の **Damage列しか見ておらず**、打点が効果文にしか
書かれていない技（全1588技中415件=26%）を全て「打点 None」にしていた。その中に
**Alakazam の唯一の攻撃 Powerful Hand**（"Place 2 damage counters ... for each card in your hand"
= 手札1枚につき20、Damage欄は `n/a`）が含まれる。

つまり脅威系の特徴が Alakazam デッキで**恒久的に死ぬ**。修正前後（12試合892決定の実測）:

| 特徴 | 修正前 | 修正後 |
|---|---|---|
| `ko_opp_active`（今KOできる） | **0.0%** | 35.0% |
| `my_best_dmg` | 平均2.05 | 平均141.1（手札7枚×20と整合） |
| `they_ko_me` | 0.28（誤値） | 34.6% |

対処: `tools/gen_atk_dmg.py` が効果文から `ATK_FIX`（固定打点37技）/ `ATK_VAR`（状態依存3技:
Powerful Hand・Thunderburst Storm・Power Whip）を生成し、生成器がヘッダへ焼き込む。
打点解決は `_resolve_dmg` **1関数に集約**した（従来は `_atk_best` と `_maxdmg_next` が
別々の可変打点処理を持ち、後者だけが Powerful Hand を名指しで特別扱いしていた＝不整合）。
**ベンチ限定の技**（Shaymin の Pinpoint Dive 等5技）はアクティブに通らないので 0 を返す。

**一般化した教訓**: 外部CSVの構造化列（Damage）を「その情報の全て」と仮定してはいけない。
自デッキの主砲が欠けていても、特徴が常にゼロなだけで例外が出ないので発見できない。

### ② 学習側に特徴の正規化が一切なかった

生の値がそのまま `nn.Linear` に入っていた。0/1フラグと `act_hp`(最大340)・
`my_best_dmg`(最大540)・`opt_vec` の一部(最大1072)が同じ層を共有していた。
訓練分割だけで平均/標準偏差を取り、npz に焼いて **全推論経路**で適用する形にした。
単独で +1.9pt。

### ③ PPO側に無言の重み欠落バグ

`PolicyTorch.from_npz` は `load_state_dict` を通さない `copy_` ループで、npzに無いキーを
黙って飛ばしていた。Dropout を入れると重みは `enc.0/enc.3` として保存されるのに受け側が
`enc.0/enc.2` なので、**`enc.2` が乱数初期値のまま残る**（例外なし）。
欠落キーで必ず落とすようにし、Sequential構成も揃えた。

### ④ スロット特徴でベンチを詰めていた

`[act] + [b for b in bench if b]` だと空きスロットが詰まり、選択肢側の `inPlayIndex` と
番号が食い違う。詰めずに `list(me.bench)` を使う形に修正。

### ⑤ 生成器が既存エージェントのディレクトリに書き込めた

`--agent-dir agents/099_alakazam_gen --tag 102` が 099 に feat_102.py を生やした
（CLAUDE.md の比較可能性ルール違反）。別タグの `feat_*.py` が既にあるディレクトリには
書かないガードを追加。あわせて、生成器が凍結済みの `agents/094_yushin_nn/nn_094.py` を
複製元にしていたのを `tools/featgen_nn.py` を正本に変更した。

## 追加した特徴（盤面 158→384次元、選択肢 24→28次元、0.36ms/決定）

コア（`tools/featgen_core.py`）に入れたので**全デッキのレプリカが自動的に恩恵を受ける**。

- **10. 対面識別**: 相手の公開領域（場・付随カード・トラッシュ・スタジアム）から
  メタ看板カード52種の観測数 `opp_seen_*` と、7系統の検出率 `oparch_*`。
  **従来これが1つも無かった**のが最大の穴。教師は対面ごとに全く違う打ち方をするのに、
  モデルはそれを条件付けられなかった（同一デッキ156952a871でも対Spidopsが
  パイロット間で17.9% vs 51.0%）。看板カードは `tools/meta_cards.py` が
  エピソードデータから弁別力（自採用率≥0.7・他系統との差≥0.6）で自動選定
- **11. 脅威とクロック**: `my_best_dmg` / `opp_best_dmg_next` / `ko_opp_active` /
  `they_ko_me` / `clock_them` / `clock_me` / `clock_diff` / `dmg_margin` / lethal判定
- **12. スロット単位の盤面**: 自分6枠×15項目（種族one-hot込み）/ 相手6枠×9項目
  （相手は自デッキ外なので種族one-hotにできず、HP比・エネ数・サイド値・次ターン打点で表現）
- **13. 資源**: 手札のカード種別内訳、デッキアウトまでのターン数
- **E. 選択肢の可能化**: `enables_evo` / `is_pre_needed` / `completes_atk` / `left_after`
  （一致率0.616で最悪だったサーチ先選択 ctx7 向け）

識別不能率は 1.75% → 1.77% でほぼ不変。**元々低く、ここは律速ではなかった**。
律速は過学習（訓練0.879 vs 検証0.754）であり、そちらが埋まった。

## 検証したこと（測定の信頼性）

- **3推論経路の数値一致**を `selfplay/check_export.py` で確認: torch / `nn_*.py`(単発numpy) /
  `batch_policy.py`(batch) が最大差 4.8e-7。標準化と Dropout(0,3配置) を通しても一致
- **ローカルにtorchを用意した**（`uv venv --python 3.12` + torch 2.2.2 + numpy<2）。
  これまで torch がローカルに無く、`_pack` の zone shape バグは Kaggle でしか見つからなかった。
  検証ループが短くなった意義は大きい
- 旧モデル（標準化なし・`enc.0/enc.2`）が新コードでも読めることを確認（後方互換）
- 正規化はチャンク処理でその場書き換え。一括だと `opt_vec`(1.95GB) の一時配列2本で
  +3.9GB になり Kaggle の RAM を割る

## 未解決・次の一手

- **Spidops枠 45.0%** が唯一の負け越し。本番では教師Yushin本人が17.9%、同一デッキの
  Majkelが51.0%（33ptの純方策差）。**対面別教師混合**（非Spidops=Yushin 3765戦 +
  Spidops=Majkel 663戦）が効く場所。今回の対面識別特徴がその前提を作った
- **勝敗ラベル `gres` を学習が一度も読んでいない**。負け試合1844件（43.3%）の全決定を
  等重みで正解として学習している。模倣の天井＝教師本人（58.1%）はここに由来する
- **補助ヘッドがゼロ**。value head（勝敗回帰）と archetype head を足すと、過学習対策・
  AWRのadvantage・価値誘導探索のV が一度に手に入る
- **MAIN階層が加算バイアスで真の分解ではない**。`c_cls = a_cls − logsumexp_{j∈cls}(s_j)` が
  必要だが `cls_head(h)` は選択肢を見ていないので**この補正は原理的に学習できない**
  → 「選択肢の多いクラスほど合計確率が勝手に膨らむ」歪みが残る
- プールv4 は 082→101 / 083→098 に更新すべき（EXP-096の忠実度ゲート合格分）
