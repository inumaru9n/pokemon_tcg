# EXP-099: 特徴の被覆監査と打点の正しさ検証 — 「正しくすると弱くなる」

- 日付: 2026-08-02
- ベース: 102_alakazam_feat2（EXP-097。プールv4 78.74%）
- 教師: Yushin Ito / sig 156952a871 / 07-17〜29 / 4254試合（勝2397 負1844 分13）

## 結論（暫定。EXP-100 で切り分け中）

**特徴を網羅的にし、打点計算を正しくしたら、プール勝率が下がった。**

| 版 | 盤面次元 | 打点の真値一致 | KO判定の一致 | val一致率 | **プールv4** |
|---|---|---|---|---|---|
| **102（現行ベスト）** | 384 | **62.2%** | **74.9%** | 0.8631 | **78.74%** [76.29-81.20] |
| 104 | 506 | 98.7% | 100% | **0.8641** | 76.29% [73.75-78.83] |
| 103 | 768 | 98.7% | 100% | 0.8616 | 73.93% [71.26-76.60] |

- 直接対戦: 104 vs 102 = **50.7%**[45.9-55.6]（互角）、103 vs 102 = 52.8%[47.9-57.6]（互角）
- **val とプールが逆順**（104 が val 最良なのにプールは最下位付近）
- `d_model` 256→384 で val 不変（0.8638 vs 0.8638）＝**容量は律速でない**
- dropout を上げると訓練も検証も一緒に下がる＝**過剰容量でもない**

**102 は4回に1回「今KOできる」と誤認している**（391/1591件）。対Spidopsでは残HP80の相手に
「240点出る」と予測して実際は0（Articuno Veil）。それでもプールでは最強。

## 検証の道具（本EXPの主成果）

被覆監査だけでは「使っているが計算が間違っている」特徴を発見できない。**3本立てにした**。

| 道具 | 何を見るか | 結果 |
|---|---|---|
| `tools/feat_audit.py` | L0可視性 / L1(ゾーン×主体×属性) / L2(ルール上の相互作用) の被覆 | 未使用28件→1件 |
| `tools/feat_verify_damage.py` | **エンジンに実際に攻撃させて**打点予測と突合 | 70.7%→99.0% |
| `tools/feat_verify_claims.py` | can_attack/can_retreat/left_ の主張 vs 選択肢リストの真値 | left_ 591件の誤り→0 |

**この3本目（真値との突合）が今日の全ての発見の源**。被覆監査では1件も見つからなかった。

## 発見した特徴の欠陥（全て被覆監査では発見不能）

1. **弱点×2・抵抗−30 が打点計算に無い** — 教師の試合の54.5%（対Marnie/Garchomp）で
   `they_ko_me` 等が2倍ぶん過小評価。エンジン実装（SetProperty.h CalcDamage）で確認
2. **Team Rocket's Articuno の Repelling Veil** — 「効果」を無効化。Alakazam の Powerful Hand は
   ダメカン配置＝効果なので完全に消える。対Spidopsの打点予測が平均+249の過大評価だった
3. **Mist Energy / Rock Fighting Energy による効果無効化** — 各×4採用。**`MIST_IDS` 定数は
   094から引き継いで存在していたのに、フラグを出すだけで打点計算に配線されていなかった**。
   対Kangaskhan 77.3% / 対Garchomp 84.2% の誤りの正体
4. **Froslass「Freezing Shroud」** — ポケモンチェックで特性持ち全員にダメカン1個。
   `_dot` は毒/火傷しか数えておらず、Marnie戦（教師の44%）でクロックが毎ターン10ずれていた
5. **`left_{cid}` が場のスタジアムを数え落とし**（591件）。`pool_counts` も同様
6. **`can_retreat` が「1ターン1回」を見ていない**

## 実装（残す）

- `tools/gen_atk_dmg.py`: 効果文から ATK_FIX(37) / ATK_VAR(3) / **ATK_COST(1556、型付き)** /
  **PROTECT(16、無効化特性)** / **CHECKUP_DMG(2)** を生成
- `tools/featgen_core.py`: `_resolve_dmg` / `_atk_scan` / `_wr_mult` / `_afford` / `_protected` に集約
- **特徴グループ機構**（`gen_featurizer.py --groups`）: base / slot_attr / resource / threat2 /
  etype / typeoh / zones / misc。生成物のヘッダに `FEAT_GROUPS` として焼き込む
- `selfplay/check_export.py`: torch / 単発numpy / バッチnumpy の**3経路の数値一致**（≤1e-6）
- **ローカルtorch**: `uv venv --python 3.12` + torch 2.2.2 + numpy<2（x86 macOSはcp312が上限）。
  アップロード前に学習・推論一致を確認できるようになった

## 教訓

- **「網羅的か」を被覆だけで判定してはいけない**。4回「網羅した」と答え、そのたびに
  被覆済みの特徴の**中身**に欠陥が見つかった。正しさは真値との突合でしか分からない
- **文字列置換の複数まとめての `assert s != o` は無言失敗する**。一部だけ成功しても通る。
  実際 `my_dmg_nullified` 等10個の特徴がアンカー1語違い（prz_me/prz_op）で入っていなかった
- **理論上の正しさで構造を変える前に、データ側の分布を見る**（EXP-098の再確認）
- **特徴が物理的に正しいことと、模倣が学習しやすいことは別**。教師は打点計算の誤りを
  犯さないので、正しい特徴は教師の行動予測に寄与しない（valがほぼ動かない）
