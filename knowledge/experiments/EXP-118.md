# EXP-118: Megaデッキの模倣は現行パイプラインでは不可能（3連敗）

- 日付: 2026-08-08〜09
- 対象: 156/159 Mega Kangaskhan ex、157/158 Mega Lucario ex（130 Mega Lopunny ex は既往）
- 状態: **rejected。プールの Mega 2枠（130/085）は据え置き確定**

## 動機

プールの最大の負債2枠（130 Lopunny 忠実度+32.1pt / 085 Kangaskhan −15.3pt、合計重み24%）と、
主力候補の多様化。直近1週間の個体勝率トップは **Mega Lucario / Majkel1337 / 0c0f140f4f
= 69.2%（n=865）** で、メタ加重でも 58.2% と現行教師（Yushin 54.4%）を +3.8pt 上回っていた。

## 結果: **Megaデッキだけが揃って落ちる**

| 枠 | 教師WR | 試合 | 決定 | クラス | 忠実度（真値との乖離） |
|---|---|---|---|---|---|
| 098 Spidops | 55.6% | 3,064 | 254,312 | 77 | ✅ +0.5pt |
| 131 Ogerpon | 55.1% | 607 | 31,343 | 31 | ✅ +2.6pt |
| 101 Marnie | 58.3% | 833 | 76,572 | 47 | ✅ +1.1pt |
| **130 Mega Lopunny** | 62.3% | 657 | 53,524 | 60 | ❌ **+32.1pt** |
| **156 Mega Kangaskhan** | 58.3% | 2,230 | 141,522 | 96 | ❌ **−36.2pt** |
| **157 Mega Lucario** | 69.2% | 865 | 50,538 | 52 | ❌ **−32.7pt** |

**試合数・決定数・クラス数のどれでも分離できない**（607試合で合格、2,230試合で失敗）。
**Megaかどうかで6件が完全に分離する。**

## Mega特有のルールを特定し、特徴に入れた（EXP-120相当）

エンジン全走査で `PokemonType::MegaEx` の使用は8箇所。**ルール差は1つだけ**:

```cpp
// State.h::getPrizeCount  — 唯一のルール差
int count = 1;
if      (pokemonType == Ex)     count = 2;
else if (pokemonType == MegaEx) count = **3**;   // 6枚で敗北＝1体で半分
```

そして**特徴器はこれを片側しか見ていなかった**:

```
opp_act_prize   ✅ あり（相手のアクティブ）
自分側のサイド価値 ❌ **なし**
選択肢の is_ex   ✅ あるが **ex と MegaEx を区別しない**
```

### ★ 配布ドキュメントと実装が食い違う

```python
# cg/api.py の CardData（配布物のドキュメント）
ex: bool  # True if Pokémon ex(**include Mega Evolution Pokémon ex**)
```
```cpp
// Api.h:243（実装）— **排他**
j.appendCommaKeyValue("ex",     card.pokemonType == PokemonType::Ex);
j.appendCommaKeyValue("megaEx", card.pokemonType == PokemonType::MegaEx);
```

実測: Mega Lucario ex は `ex=False / megaEx=True`。つまり従来の `is_ex` では
**デッキの主役が 0.0（ただのポケモン）**になっていた。156では通常exが7種（1.0）ある中で
**Megaだけが0.0**という逆転が起きていた。

**追加した特徴**: 盤面 `my_act_prize` / `my_bench_prize_max` / `my_prize_exposure` /
`opp_bench_prize_max`、選択肢 `is_mega_ex` / `opt_prize`（OPT_DIM 29→31）。

実装中に1つ穴を踏んだ: 最初は場のポケモン限定にしていたため、**Megaが選択肢に出た20回中18回が0.0**。
**手札からMegaへ進化する選択こそリスク判断が要る**ので、カードIDだけで決まる形に移した。

### 効果: **再現しない**

| | vs random | vs 104 | 真値 | 乖離 | 改善 |
|---|---|---|---|---|---|
| 156 Kangaskhan（Mega特徴なし） | 84.0% | 8.0% | 44.2% | −36.2 | |
| **159 Kangaskhan（あり）** | 89.0% | 8.0% | 44.2% | −36.2 | **+0.0pt** |
| 157 Lucario（なし） | 97.0% | 32.5% | 65.2% | −32.7 | |
| **158 Lucario（あり）** | 98.5% | 38.0% | 65.2% | −27.2 | **+5.5pt** |

Lucarioで+5.5pt（n=600でCI±3.9ptなのでぎりぎり有意）だが、**Kangaskhanでは±0**。再現しない。
`vs random` は両方で改善しているので特徴自体は機能しているが、**強い相手に対する壁は動かない**。

## 死因は特定できていない

サイド枚数の欠落は**実在する表現の穴**だったが、**3連敗の原因ではなかった**。
エンジンのルール差は `getPrizeCount` 1箇所しかないので、
「Mega特有のルールをもう1つ見落としている」という線は消えている。

残る仮説（未検証）:
- **教師が強いほど模倣が難しい**: 合格3枠は 55.6/55.1/58.3%、失敗3枠は 62.3/58.3/69.2%
- Megaデッキは1体の価値が突出しており、方策の繊細さの要求水準が高い

## 恒久的に残るもの

1. `tools/act_freq.py` — **実プレイの行動分布 vs 教師**の突合。`end` 膨張で
   covariate shift を検出する。**val一致率では検出できない失敗を、忠実度ゲート
   （対戦2本・40分）の前に予見できる**（156は vs random 84.0% と end膨張+3.4ptで予見できていた）
2. `featgen_core` の Mega/サイド枚数特徴（原理的に正しい修正。今後の枠で有効）
3. **配布ドキュメントを信じずエンジンのJSON出力を確認する**という運用則

## 判断

**プールの 130 Lopunny / 085 Kangaskhan は据え置き**（現行のほうが乖離が小さい）。
**主力候補としてのMega系（Lucarioのメタ加重58.2%）も断念**。
