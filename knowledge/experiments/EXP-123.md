## 3. ★ 回収系は増やしても減らしても負ける

使用率監査（117の実対戦38試合、手札に来たとき使われた率）:

```
Sacred Ash **23%** / Lana's Aid **30%** / Night Stretcher **38%**
Enhanced Hammer 44% / Xerosic's 46% / Fezandipiti 52%
Hilda 66% / Boss's 67% / Enriching 81% / Rare Candy 87% / …
```

最下位3枚がちょうど**回収系の1枚積み**だったので、両方向に振った。

```
**減らす**  179（2枚減）**−6.59pt** / 178（3枚減）**−9.07pt**
            切った枚数と損失が単調。対ミラー −20.6 / 対Ogerpon −17.4 が大きい
**増やす**  188（Night Stretcher/Sacred Ash/Lana's Aid を各+1、
            Poké Pad 4→2・基本エネ 2→1 で枠を作る）**−3.06pt**
            対Dragapult −5.8 / 対Kangaskhan −4.7 / 対Marnie −3.4
```

> **教訓: 使用率の低さは「価値が低い」でも「引けていない」でもなく、
> 「その枚数がちょうど良い」ことを意味しうる。** EXP-108のEnhanced Hammer
> （使用率44%・抜くと対Kangaskhan −14.5pt）と同じ構図が、逆方向でも成立した。

Poké Pad を削れると考えたのは「手札増減±0だから打点に響かない」という理屈だったが、
**サーチによる盤面形成の価値**を見落としていた。

## 4. デッキの核: Powerful Hand は手札1枚につき20ダメージ

```
ATK_FIX[(743,'Powerful Hand')] = ('hand', **20**, 1, 1)
実測  平均手札 **9.18枚** → 平均打点 約184 / 手札12枚以上が31.3%の決定
```

**引く行為そのものが打点**という構造。攻撃コストは1エネなので、エネルギー枚数（7枚）は論点でない。
これが「回収系も Poké Pad も抜けない」理由の背景にある。

## 5. デッキ空間は尽きた

117の周辺を8方向から突いて、すべて負けまたは判別不能:

| | 変更 | 結果 |
|---|---|---|
| 121 | Dudunsparce 4枚 | vs117 50.0%（3枚で足りている） |
| 118 | +1エネ / −1 Hilda | 効果ゼロ |
| 119/120 | 117の部分集合 | 117に負け |
| 123/124 | Enhanced Hammer −2 / −1 | 棄却（対Kangaskhan −14.5） |
| 178/179 | 回収系 −3 / −2 | **−9.07 / −6.59** |
| 188 | 回収系 +3 | **−3.06** |

残る未検証は Boss's Orders 3→4 等の**±1枚**だけで、プールの分解能（±2pt）以下。
**117が+2.22ptで当たったのは5枚入れ替えという大きさ**による。

DECK_COUNTS の22種以外を入れるには**再抽出+再学習が必須**（特徴キーと行動クラスが変わる）で、
かつ模倣学習なので「そのデッキを使う教師データ」が要る。締切まで3日では非現実的。

## 6. デッキを変えるとき実装のどこを触るか

```
**枚数だけ変える場合（0枚にするのも含む）→ 2箇所だけ**
   1. deck.csv
   2. feat_*.py の **DECK_COUNTS（キーを保って値だけ差し替える）**
```

117のデッキで特徴器を**作り直すと壊れる**（実測）:

```
DECK_COUNTS キー 22 → **20**（Shaymin 343 / Nighttime Mine 1266 が消える）
SPECIES 7 → 6 / **CLASSES 65 → 57**（ab_shaymin / atk_shaymin_0 / attach_*_shaymin_f …）
**board 456 → 517（+61）** → モデルと不一致 → **_NN_ACTIVE=False で無言フォールバック**
```

実際この事故を踏んだ: 178/179 の初版で `base` を deck.csv から作ったため
0枚の343/1266がキーごと消え、**5次元欠けたまま errors=0 で対戦が進んだ**
（vs random が 20/20 → 18/20 に劣化。main.py のガードは初回決定で検知して
stderr に出すが、run_match は stderr を捨てるので気づけない）。
**必ず FEAT_KEYS / CLASSES の一致を検証してから対戦に回すこと。**

## 7. ★ 本番リプレイによる負け方の分解（104+186 の83戦・39敗）

```
サイドレースで押し切られ（相手あと1枚）  **12敗（31%）**
**ベンチ切れ**                        **12敗（31%）**
**山札切れ**                          ** 8敗（21%）**
その他 4敗 / 序盤崩壊 3敗
```

### 対Mega Lopunny は 8敗中5敗が山札切れ

```
自サイドを **6枚残したまま**山札が尽き、相手の山は18〜21枚残っている
＝ **こちらだけが一方的に引き切っている**
```

Alakazamは手札＝打点なので引くのが正義だが、Lopunnyは Mega1体で受け続ける遅い盤面で
決着に必要なターン数が長く、60枚では足りない。

**方策の「引きすぎ」ではない**（実測）:

```
特性(ABILITY)を選べたMAIN決定 1,344件での発動率
   山0〜3枚 20% / 4〜7枚 18% / 8〜12枚 12% / 13〜20枚 18% / 21〜60枚 18%
→ 山札が減っても発動率はほぼ一定で、そもそも滅多に引いていない
```

トラッシュの素材はある（山0〜3枚の局面でポケモン平均**6.0枚**・5枚以上が**72%**）ので
Sacred Ash は撃てる状態にあるが、1枚積みで引けていない（使用率23%）。

**ただしこの負け筋はプールで判定できない。** プールの130 Lopunny は本番より
**+38pt 弱く**（プール82.1% vs 本番44%）、長期戦にならないので山札切れが起きない。
