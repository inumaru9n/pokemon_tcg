# EXP-071: 時系列CV平均（連続ブロック6-fold） — 071_cvavg

- 日付: 2026-07-19
- 動機: EXP-070でモデルチューニングが効いた → 同一データ・同一ハイパラのままCV平均でさらに詰まるか
- エージェント: `agents/071_cvavg/`（070のコピー。ルール・特徴量・データ全て不変、平均するだけ）
- 状態: **rejected**（増分+0.57pt < ゲート+1pt。かつ安い移植経路が成立しない）

## 手法

070と完全同一のデータ（train 07-09..13 / val 07-14 / test 07-15、再収集して行数一致を確認:
96,023 / 24,085 / 24,559、errors=0）とハイパラ（lr=0.01 / num_leaves=31 / min_data=100）を固定し、
**1日=1連続ブロックの6-fold**でK本のモデルを学習して確率平均する。

| fold | val (early stopping) | n_train |
|---|---|---|
| f1 | 07-09 | 109,975 |
| f2 | 07-10 | 103,346 |
| f3 | 07-11 | 93,906 |
| f4 | 07-12 | 98,464 |
| f5 | 07-13 | 98,826 |
| f6 | 07-14 | 96,023 ← 070と同一の切り方 |

ランダムK-foldは時系列リークになるため不使用。test 07-15 は学習にもearly stoppingにも一切使わない。
ハイパラは070で選定済み＝ここでは選定しないので、testを増分測定に流用できる。

## 結果

| | test 07-15 一致率 |
|---|---|
| f6単発（=070と同一） | **0.7767** ← EXP-070の0.7767と完全一致（再現性確認） |
| **CV平均 K=6（確率平均）** | **0.7824（増分 +0.0057）** |
| CV平均 K=6（生スコア平均） | 0.6624（**-0.1143**、確率平均との予測一致0.804） |

Kに対する飽和: K=2 0.7830 / K=3 0.7826 / K=4 0.7839 / K=5 0.7840 / K=6 0.7824 —
**K=2で頭打ち**。fire=1192、CV正解565 / 単発正解425（net +140 / 24,559 = +0.57pt）。
全foldの best_iter は 1291〜1881 で cap(8000) は非拘束。

## 結論

**rejected。理由は2つとも独立に致命的。**

1. **増分 +0.57pt はゲート(+1pt)未達**。EXP-070は一致率+5.1pt→アリーナ+3.2ptだったので、
   +0.57ptはアリーナで数千戦回しても検出できない。**同一データ・同一ハイパラのGBTは
   バリアンスが元々小さく、平均する余地がない**（K=2で飽和がその証拠）
2. **安い移植経路が成立しない**。npz形式は「全ツリーのleaf値をクラス別に総和→argmax」なので
   生スコア平均ならツリー連結+1/K倍でmain.py無変更のはずだったが、生スコア平均は**-11.4pt**。
   logit平均＝確率の幾何平均のため、1foldが真クラスに極端に低い確率を与えると拒否権を持つ。
   確率平均を本番でやるにはmain.pyにモデル境界とper-model softmaxが必要＋推論6倍（~490ms/手）

**「モデル側の残りしろ」の所在が変わった**: 070のチューニングは効いたが、それは
「学習設定が最適でなかった」分の回収であって、アンサンブルで取れる分散はもう無い。

## 副産物（本命の発見）

CV平均の測定中、**070実機(npz経路)の一致率 0.7596 が、同一モデルのlightgbm経路 0.7767 より
1.7pt低い**ことが判明。best_iter=1291×37クラス=47,767木でmodel_070.npzと完全一致するので同じモデル。
差はモデルの外側（ルール層）から来ている。turn帯別に分解:

| turn帯 | モデル | 070実機 | 差 |
|---|---|---|---|
| t1-2 | 0.937 | 0.867 | **-7.0pt** |
| t3-5 | 0.805 | 0.805 | 0 |
| t6-9 | 0.742 | 0.740 | -0.2 |
| t10+ | 0.747 | 0.719 | -2.8pt |

- **t1-2の正体**: `main.py:2532` の `if ... and obs.current.turn >= 2:` により
  **turn 1 ではMLレイヤが呼ばれず052ルールのみ**。turn 1 は n=708（全決定の2.9%）で
  ルール 0.790 に対しモデル ≈0.962（**17pt差**）。全体寄与 ≈ +0.5pt。
  このガードは lethal探索（turn 2以前に成立しない）由来で、後からMLレイヤを同じ分岐に
  相乗りさせた際に引き継がれた**設計事故**と見られる。モデルはturn 1のデータで学習済み
- **t10+の正体**: `_lethal_search` がモデルより先に走り上書きしている。これは正着計算なので
  一致率が下がっても棋力は下がらない可能性が高い（agreement ⊥ 棋力）。**触らない**（EXP-069の教訓）

## 次への申し送り

- turn 1 へのMLレイヤ拡張（ガードを `turn >= 1` に）は**一行の変更**で試せる。ただし
  期待効果は一致率+0.5pt程度で、本EXPでrejectした+0.57ptと同オーダー。

  「序盤は重要だからレバレッジが高いはず」という理屈で採用してはいけない**。アリーナで測ること

  残る大きな伸びしろは **I-109（自己対戦RL）** に絞られた
