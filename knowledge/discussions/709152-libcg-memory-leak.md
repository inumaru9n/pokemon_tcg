# libcg.soのメモリリーク（14v）

## 3行サマリ
- 連続対戦でRAMが線形増加し、5万戦/100万stepでKaggleノートの30GBが枯渇する報告
- 有力原因: visualize_data()のctypes c_char_p戻り値がネイティブ側バッファを解放できない（対戦ごとに数MB蓄積）
- 回避策: visualize_data()を呼ばない、定期的にプロセス再起動（チェックポイント運用）

## 取れる情報
- ★ 大規模自己対戦（RL/データ収集）ではワーカープロセスをN戦ごとに使い捨てる設計が必須
- 我々のarena（ProcessPoolExecutor、1シリーズ=最大数百戦/プロセス）とtrain_012（2000戦/プロセス）は現状規模なら安全圏
- battle_start/select自体のリーク疑いもあり、visualize回避だけでは不十分な可能性
