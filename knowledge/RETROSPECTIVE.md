### 1.2 上位解に共通する設計

1. **BC初期化 → PPO自己対戦 → デッキ別スペシャリスト**。24位解はその前に
   「GBDT教師を作り、その教師に15,000〜30,000試合させて状態分布を広げる」段を挟む
2. **小さいモデル + 大量の経験**（1M〜12M級が主流。117Mを回した14位は例外）。
   推論速度が経験量を決めるので、C++/AVX2で1ms/決定まで詰める
3. **報酬は最終勝敗のみ**（15位が明言。ダメージやサイド獲得は報酬にしない）
4. **手書きルールで個別のミスを塞がない**（15位が明言）。直すのは観測表現と学習のさせ方
5. **相手の隠れ情報は入力にしない**。自分の山/サイドも belief（初期デッキ−観測）として渡す（24位）
6. **盤面と選択肢を同一系列に入れて self-attention → pointer で選ぶ**。複数選択は選択済みを条件に逐次（24位）
7. **デッキは「ラダーのシェア」ではなく「上位チームの使用率」か「RLで伸ばせるか」で選ぶ**。
   上位が選んだのは Slowking / Dragapult / Ogerpon+Meganium で、シェア最大の Grimmsnarl ではない
8. **探索は使うなら on-policy な value head と一緒に**（後述）

## 第2部: 我々のソリューションの何がいけなかったか

### 一言でいうと

**模倣で作った強い方策を「守るべき資産」として扱い、それを捨てて作り直すための予算（時間と規模）を
一度も確保しなかったこと。**

これが単一の根で、他は全てその帰結である:

| # | 帰結 | 技術的な現れ |
|---|---|---|
| 1 | RLを**SL方策のKLアンカー付き微調整**として設計した | 初期方策が飽和（実効選択肢1.29/8、選択手の確率0.856）→ 勾配に比較情報が乗らない |
| 2 | 停滞を **1/14〜1/573の規模**で「この構成は行き詰まり」と一般化した | 連続最長ラン60,000試合=6時間。14位の小モデルですら135M env step |
| 3 | 残り1ヶ月を**同じ方策の磨き込み**に使った | ±1ptの改良を、LB実分散±100ptの下で追った（EXP-124〜142で13実験中11棄却） |
| 4 | デッキ乗り換えの基準が**「模倣できるか」**になった | Dragapultを MAIN一致0.67 で棄却（EXP-127）。メタは8月にDragapultへ移っていた |

**補強要因（独立）**: 測定装置が「精密に測れるもの」に寄っていた。
val一致率とプール加重は小数点以下まで再現するが、前者は強さと直交する場面が多く（EXP-080等）、
後者は絶対値が本番比+16pt甘い（EXP-119）。**測りやすい量を最適化していた**。

以下は影響の大きい順の詳細。

### 原因1（最大）: RLを「模倣の後付けの微調整」としてしか設計しなかった

**事実の確認（2026-09-13に記録を読み直して訂正）: 我々はRLをやっている。**
やっていないのではなく、**やった形が構造的に動かない形だった**。

| 段階 | いつ | 何をしたか | 結果 |
|---|---|---|---|
| EXP-016 | 07-07 | BC初期化 + REINFORCE 自己対戦、12イテレーション×600試合 | 初期BC 0.284 から改善せず → rejected |
| EXP-095 Stage 0 | 07-27 | **ベクトル化自己対戦生成器**（1プロセス24バトル並行、アリーナと勝敗32/32・手数32/32一致、バッチ推論の数値一致 3.8e-06）。**ローカル5ワーカーで 63,266試合/時** | 事前登録の検証を全項目PASS |
| EXP-095 Stage 1 | 07-27 | critic 学習。ターン5以降 **AUC 0.857**（閾値0.75）、2万試合で飽和 | **キルゲートPASS** |
| EXP-095 Stage 2a | 07-28 | 探索温度の決定（先後入替 n≈1,020） | **T=0.7 採用**（argmax比 −3.7pt） |
| EXP-096 Stage 2c | 07-30頃 | **PPO本体を実走**（`selfplay/ppo.py` + `ppo_train.py`）。相手を101に固定し、**3条件×20イテレーション×1,000試合**の統制比較 + 特権情報/学習率のアブレーション | **停滞。方策を動かすほど悪化** |

PPOの結果は明確だった:

| 最終KL（方策の移動量） | vs 101 argmax |
|---|---|
| 0（未学習） | **45.6%** |
| 0.030（lr 1/3） | 43.9% |
| 0.087〜0.090 | 41.5〜41.6% |

**動かすほど悪くなり、動かさなければ元のまま**＝勾配に行動固有の信号がほとんど無い。
原因まで自分で特定している（EXP-096）:

1. **探索が構造的に成立しない** — argmax一致率89.3%、**実効選択肢1.29個**（平均8個中）。
   9割の決定で「どうせ選んでいた手」を選ぶので勾配に比較情報が乗らない。**温度では直らない**（T=2.0でも1.92個）
2. **信用割当の距離** — 報酬は終端±1のみ、1試合約80決定。自分の決定の間に相手の1ターンとドローが挟まる
3. **飽和方策に対するクリップの非対称** — 選んだ手の確率が平均0.856。クリップ±20%では
   **上げる余地がほぼ無く、下げる余地は大きい**。負の優位性が多数派だと**模倣で得た自信のある手を削る**方向に偏る

**そして、この3つは全て「BC初期化」から来ている。**

15位は**ランダム初期化から始め、BCも人間デモも一切使わなかった**。
ランダム方策のエントロピーは最大（実効選択肢≒8）で、飽和もクリップの非対称もなく、探索は無料である。
我々は EXP-095 の時点でこの危険を自分で書いていた:

> 選択肢が平均8個（最大エントロピー ln8=2.08）なのにT=1.0でもエントロピーは0.406。
> 教師を82%忠実度で模倣した結果、確信度の高い方策になっている。
> **KLアンカーと低エントロピーが両方「変わるな」に働く**

**にもかかわらず、設計を「SL方策をKLアンカーで守りながら改善する」から変えなかった。**
`selfplay/ppo.py` の冒頭には「初期値 = 094（模倣で得たSL方策）。**SL方策へのKL正則化を最後まで掛ける**」
と書いてある。つまり **RLは常に模倣の付属物**であり、模倣を捨てる選択肢は一度も検討されていない。

そして 2026-08-04（EXP-109）に「**PPOは『まず3.7pt損してから取り返す』構造。残り12日で着工する
事前確率は低い**」と判断して打ち切り、以降はSLの特徴改良とアーキ微修正に戻った。

**取るべきだった結論**: 「このゲームでRLは動かない」ではなく
**「BCアンカー付きRLは動かない。動かすならBCを捨てる」**。
24位は BC（GBDT教師）を使いつつPPOを成功させているが、彼らの教師は**わざと弱い**
（最終PPOモデルの約200レーティング下）ので飽和しない。**教師が強すぎるとRLが効かない**という
非直感的な構造に、我々は正面から当たっていながら気づかなかった。

### 原因2: 規模が1〜2桁足りないまま「この構成では行き詰まり」と判定した

我々が実際に回したRLの総量（EXP-096）:

| ラン | 規模 | env step換算 |
|---|---|---|
| リーグ本走（自己30%/過去20%/SL初期10%/101 35%/098 5%） | 2,000試合×30iter = **60,000試合**・約6時間 | **約960万** |
| KL係数スイープ（3条件） | 1,000×10×3 = 30,000試合 | 約480万 |
| E1 相手固定 | 1,000×20 = 20,000試合 | 約320万 |
| E2/E3 特権情報・lr（3条件） | 1,000×20×3 = 60,000試合 | 約960万 |
| **合計** | **約17万試合** | **約2,700万** |

比較（env step = 両者の決定点、14位の定義と同じ）:

| | 連続1ランの規模 | 対 我々のリーグ本走 |
|---|---|---|
| **我々（リーグ本走）** | **960万** | 1× |
| 14位 小モデル(16.7M) | **135M** | **14×** |
| 14位 大モデル(117M) | **1.68B** | **175×** |
| 15位 | **5.5B** | **573×** |

生成能力は **63,266試合/時（実測）** あったので、14位の小モデル規模（135M ≈ 84万試合）でも
**約13日**、15位規模なら8〜22日で到達できた計算になる。Stage 0完成の07-27時点で締切まで20日。
**RTX4090 1枚（15位）・RTX3090（27位）は特別な計算資源ではない**。
EXP-095ではKaggle上でCRNパッチ入り libcg.so を37秒でビルドでき、
**RLループをKaggle Notebook内で完結できる**ことまで確認している。

打ち切りの判断は 2026-08-01（EXP-096「方針転換」）で、
**60,000試合＝6時間のラン1本**を主要な根拠にしていた。

（注: 基盤への投資自体は十分に行っている。ベクトル化自己対戦・バッチ推論・critic・PPO・
リーグの各コードは `selfplay/` に41本のスクリプトとして残り、工程別のms/決定内訳まで実測済み。
**足りなかったのは基盤ではなく、それを回した時間である**。）

### 原因3: デッキ選択が「模倣できるか」で決まった

[EXP-127（8/12）](experiments/EXP-127.md)で我々は正しく観測している:

```
上位7組のうち5組がDragapult
対面別          Marnie  Alakazam  Lopunny
  186（我々）     43%     62%      43%
  Dipam(最終3位)  72%     85%      84%
  flg (最終4位)   68%     69%      63%
```

そして Dragapult のSLレプリカを作ったが MAIN一致 0.67（Alakazam は 0.83）で「模倣が成立しない」と棄却し、
**Alakazam に留まった**。その分析自体は正しい（Dragapultの勝ち筋は Crushing Hammer 等の妨害の使いどころで、
相手の次の行動に条件付くため盤面要約から識別不能）。

**間違っていたのは結論の向き**である。「模倣できないデッキ＝リプレイからは到達できない＝RLでしか到達できない」
のであって、上位が Dragapult / Slowking を選んだのはまさにそこに価値があったからだ。
**手法が戦略を決めてしまった**（持っている道具が模倣だけだったので、模倣できるデッキを選んだ）。
結果、最終評価期間を**フィールド勝率44.7%のデッキ**で戦った。

#### 補足: 「Alakazamは構造的に不利だった」は**言いすぎ**（2026-09-13の自己訂正）

選定時点（07-17〜29）の教師 Yushin Ito は**LB1位**で、Alakazamは最大シェアのアーキタイプだった。
そして我々自身の本番実測（[EXP-119](experiments/EXP-119.md)、104 の246戦）は**全体54.5%**＝勝ち越している。
「構造的に不利なデッキを選んだ」という総括は事実に合わない。**選定そのものは当時の基準では正しい**。

支持できるのは、もっと限定的な3点だけ:

1. **最大対面に方策で埋めにくい非対称があった** — Marnie は遭遇38.2%で勝率41%。機序は
   [EXP-109](experiments/EXP-109.md): Grimmsnarl ex の Shadow Bullet **180** に対し Alakazam は **HP140**
   ＝毎ターン一撃圏。攻撃できたのは自分のターンの**52%**で、攻撃時のKO率は92%（打点は足りている）。
   **律速は判断ではなく「攻撃役を毎ターン失って建て直すこと」**
2. **最終メタで評価が落ちた** — 08-15時点でアーキタイプのフィールド勝率 **44.7%**、
   上位帯はDragapultに移行（上位23人中12人）。**選定が正しかった時期と、評価された時期がずれた**
3. **同じフィールドに対する差** — [EXP-127](experiments/EXP-127.md)の対面表で
   186（我々）は Marnie 43% / Lopunny 43%、Dipam（最終3位）は 72% / 84%、flg（最終4位）は 68% / 63%。
   ただし**これはデッキ効果と方策効果が交絡している**（相手はRLで鍛えた方策）ので、
   デッキ単独の不利の証拠にはならない

**逆に、支持できないもの**: 「BC一致0.83＝方策の伸びしろが小さい」。
一致率が測っているのは**教師の選択の予測しやすさ**であって、教師と最適手の距離ではない。
実際、このデッキ上でも方策改善は強さに転移している（[EXP-097](experiments/EXP-097.md):
val 0.754→0.8646 でプール +10.5pt・vs094 65.2% / [EXP-113](experiments/EXP-113.md):
132 vs 117 直接 53.0% 有意）。**教師自身が58.1%なのだから、模倣しやすさに関わらず上には余地があった**。

したがって原因3の正しい形は「不利なデッキを選んだ」ではなく、
**「7月の基準で選んだデッキを、メタが動いた8月に再評価せず、乗り換えの判断基準を"模倣できるか"に置いた」**である。

### 原因4: 探索を殺した実験が、すべて「価値関数がない状態」で行われた

我々は探索を4回殺している: EXP-006（ビームサーチ）/ EXP-053（毎手MC）/ EXP-125（推論時ExIt）/
EXP-132（ExIt蒸留の全軸）。結論は「このゲームで探索は成立しない」だった。

しかし [736121](discussions/736121-dragapult-bc-rl-mcts.md) の実測:

> **BC value head での探索は −20〜30点。PPO value head での探索は +50〜70点。**

我々の探索実験の価値関数は全て**手書き or BC由来**（EXP-012のロジスティック/MLP、EXP-124の決定化ロールアウト）。
つまり**探索が死んでいたのではなく、on-policyな価値関数を持っていなかった**。
ここで**原因1（RLなし）が原因4（探索なし）を生み、原因4の「探索は無理」という結論が
原因1の再開動機を消す**という循環が閉じていた。

### 原因5: 8月の1ヶ月を、LBの分解能より細かい差の追求に使った

同一バイナリ `186_alakazam_v8` のLB実測は **1028.8 / 942.5 / 923.6 / 829.9（幅199pt）**。
一方、候補間のローカル差は **117=73.0 / 222系=72.5 / 187=72.3 / 186=70.9 の 2.1pt** に収まっている。
**LBの1サンプルはローカル差の全域を覆い隠す**。これは我々自身が提出記録に書いていた。

それでも EXP-124〜142（8/12〜8/17の13実験）は ±1pt 単位の改良を追い、
**採用は EXP-136（+1.06pt）と EXP-134の一部だけ、残り11本は棄却**。
対象は LSTM除去・cross-encoder化・対象カード埋め込み・詰み層など**アーキテクチャの微修正**で、
EXP-123 で自分が「デッキ空間は枚数調整の範囲で尽きた」と書いた後も同じ空間を掘り続けた。

さらに、その定規自体が歪んでいることも実証済みだった（[EXP-119](experiments/EXP-119.md):
プールの絶対値は本番比 **約16pt過大**、084 Alakazam枠は+31pt、130 Lopunny枠は+41pt甘い）。

**「測れない差を測ろうとして1ヶ月を使った」** のが8月の実態である。
分散が改善幅より桁で大きいと判明した時点で取るべき手は「サンプルを増やす」ではなく
**「分散を超える大きさの改善を作りにいく」**＝原因1に戻ることだった。

### 原因6: メタ更新の規約を自分で破った

CLAUDE.md に **「締切直前に必ず重みを更新する」「重み更新は既存の対面別結果を再集計するだけでよい」**
と書いてあるのに、`knowledge/episodes/` の定期メタレポートは **2026-07-29 が最後**。
プールの重みは 07-23〜29 のスナップショットのまま最終提出まで使った。
その間に Grimmsnarl は 33.7%→25.1%、Dragapult は 4.1%→12.5%→（評価期間）26.6% と動いている。
**最も安い改善（再集計だけ）を実行しなかった**。

### 原因7: 最終週の提出枠の使い方

最後の3提出は**同一バイナリの反復サンプリング**に充てた（186の3〜4サンプル目）。
分散推定としては筋が通るが、σ≈100pt に対し n=4 では平均のCIが±50pt 程度で、
**意思決定に使える精度には届かない**。同じ枠を「Dragapult系の候補を1枠で試す」に使えば、
少なくとも情報は得られた（ローカル評価が信用できないのだから、本番A/Bこそが唯一の定規だった）。

## 第4部: 次回のための6つのルール

1. **「その手法の天井はどこか」を最初に見積もり、天井が目標より低いなら着手しない**。
   模倣学習の天井は教師の勝率であり、これは開始前に計算できた
2. **強い教師からのBC初期化は、RLの前提ではなく障害になりうる**。
   模倣忠実度が上がるほど方策は飽和し（実効選択肢1.29/8）、方策勾配から比較情報が消える。
   **RLを本気でやるならランダム初期化（15位）か、わざと弱い教師（24位、最終比−200レート）を使う**。
   「BCで初速を稼いでRLで伸ばす」は、教師が強いときには成立しない
3. **否定的な結論には必ず「どの条件下で」を付ける**。我々の結論は正しくは
   「BCアンカー付きPPOは900万決定の規模では動かない」であって「RLは動かない」ではなかった。
   **条件を落とした一般化が、その後1ヶ月の路線を決めてしまった**（原因1・原因4とも同じ構造）
4. **打ち切りの前に、規模を1桁上げる**。我々のPPO診断は各条件2万試合＝**約20分**の生成で下した。
   同じ基盤で連続8〜22日回せば15位の規模に届いた。
   **「20分で信号が出ない」は「この方向が駄目」ではなく「まだ測っていない」**
5. **本番の分散を測ったら、改善幅をそれと比べる**。改善幅 < 分散 なら、実験を続けるのではなく
   **実験の対象を変える**（微修正 → 路線）
6. **デッキは「上位チームの使用率」で選ぶ**。ラダー全体のシェアは下位帯の分布であり、
   我々が戦う相手の分布ではない（737107の「レート帯でシェアが逆転する」が決定的）
