# a-sample-rule-based-agent-mega-abomasnow-ex-deck.ipynb

Kiyota公式サンプル。91票。"Beginner Friendly" と明記された最もシンプルなサンプル。4ノートブック中もっともコード量が少なく、
初学者向けの最小構成リファレンスとして位置づけられている。

## 3行サマリ

- デッキ: Mega Abomasnow ex（Hammer-lanche: 山札上6枚を捨てて捨てた基本水エネ1枚につき100ダメ）＋Kyogre（Riptide: トラッシュの基本水エネ枚数に比例したダメ）の2枚看板。基本水エネルギー34枚（デッキの57%）という極端な高エネルギー比率が特徴。
- 方策: AttackPlanのようなグローバル計画は無く、`switch_index`という単一変数で「今どちらのアタッカー（Abomasnow ex/Kyogre）をアクティブに置くべきか」だけを判定するシンプルな設計。`prefer_ky = op_active_hp <= 20 * discard_counts[Basic_Water_Energy]`（Kyogreで安全にKOできるならKyogre優先）という一点だけの切り替えロジック。
- コード全体で条件分岐の深さ・カード種類がLucario/Dragapult/Ionoより明確に少なく、「まず動くルールベースを作る」の教材として設計されている。

## 盗めるアイデア

- 「トラッシュ蓄積量に比例してダメージが伸びる」タイプの技（Hammer-lanche/Riptide）の評価を`discard_counts[Basic_Water_Energy]`のような単純なカウンタ参照だけで組める、という最小実装例。同系統の技を持つデッキの雛形として使える。
- 2種の代替アタッカーを持つデッキで「どちらが今有利か」を単一のbool/indexフラグで判定するミニマル設計は、複雑なAttackPlanを組むコストに見合わないシンプルなデッキ（アタッカーが2体までなど）では十分な代替案になりうる。
- `Hammer-lanche`使用時、`if op_active_hp <= 200: score -= 100 else: score += 100` として「オーバーキルになりそうな時は別の技/カードを優先させる」という簡易オーバーキル回避ロジック。

## 注意点・疑問

- 要検証: Hammer-lancheは「山札の上から6枚を強制的に捨てる」効果のため、自分のデッキアウト（山札切れ）リスクを直接的に高める攻撃だが、このノートブックには`no_draw`のような山札残数の safeguard が見当たらない（Dragapult/Iono版にはある）。長期戦でのセルフミル自滅リスクは未検証。
- サブアタッカーが2体のみのシンプルなデッキ設計のため、他ノートブックのような「相手の特定カードを名指しでブラックリスト」する調整（`pokemon_score`のような相手依存の狙い分け）が無く、対面ごとの最適化余地が大きい（＝改善しやすい教材、という側面もある）。
