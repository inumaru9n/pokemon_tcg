# a-sample-rule-based-agent-iono-s-deck.ipynb

Kiyota公式サンプル。123票。Intermediate Level。テンプレート骨格は共通だが、AttackPlanのようなグローバル計画オブジェクトを
持たず、各コンテキストで独立にスコアリングする「よりシンプルな」実装スタイル。

## 3行サマリ

- デッキ: Iono's Voltorb（無進化・低リスク、Voltaic Chain: 20+付いてるエネ数×20ダメ）をメインアタッカーに、Bellibolt exの特性「Electric Streamer」で手札の基本雷エネを**1ターンに何枚でも**付けてVoltorbやBellibolt exを急速強化するコンボデッキ。Kilowattrelの特性でドロー、Canariで雷ポケモンをまとめてサーチ。
- 方策: AttackPlanのような事前計画オブジェクトは使わず、`SWITCH`/`TO_ACTIVE`選択時にその場で「20+エネ数×20 >= 相手HP」を判定してワンショットKO可能なら score += 100000 する即時判定型。攻撃対象選択（Boss's Orders等）のロジックが薄く、相手ベンチへのガストは考慮が弱い。
- 「1ターンに複数エネルギー付与可能」という特殊能力を持つデッキのため、`state.energyAttached`（通常1ターン1枚制限のフラグ）を一切参照していない点が他デッキとの明確な違い。

## 盗めるアイデア

- 「エネルギー加速コンボ」型デッキの評価テンプレート: `field_hand_counts`（場+手札の合計枚数）で「あと何枚necessaryか」を判定し、`Buddy_Buddy_Poffin`のようなサーチカードの優先度を進化ラインの充足度で調整するパターン（`field_pokemon1`/`field_pokemon2`のグルーピング）。
- ワンショットKO判定を「送り出す/交代先を選ぶ」段階で先に評価する設計（`20 + energy_count*20 >= op_active_hp`）。AttackPlanを持たない分シンプルで移植しやすいが、後述の通り一貫性は犠牲になる。
- `Max_Rod`のような「トラッシュから複数回収するサポート」を手札スコアで別枠の高評価（1000点、他の手札カードは最大160点程度）にして「絶対に捨てない」ように保護している設計は分かりやすい。

## 注意点・疑問

- Mega Lucario ex版のような統一AttackPlanが無いため、「エネルギーを付ける先」と「実際に攻撃するポケモン」の一貫性が担保されにくい設計に見える（例えば、ベンチの育ったVoltorbに気づかずアクティブの違うポケモンへエネ付けするリスクがないか要検証）。実戦での行動一貫性は要検証。
- 相手のベンチ狙い（Boss's Orders相当のガスト）に関する評価が他デッキ（Lucario/Dragapult）ほど作り込まれておらず、相手の弱い/育っていないポケモンを場に固定する戦術への対応は薄い可能性がある。
